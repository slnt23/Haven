# ADR-005：MVP 范围与项目入口

- **Status**: Accepted (2026-09-01)
- **Deciders**: Haven 项目组
- **Date**: 2026-09-01
- **Depends on**: ADR-001

## Context

原需求把多个独立产品级能力同时列为 MVP，无法用一条用户路径快速验证产品价值；仓库当时也没有已实现的产品入口。

## Decision Drivers

- 必须用一条用户路径快速验证产品价值
- 必须以 Agent 决策循环形态交付
- 0.0.1 只做高血压垂直闭环

## Considered Options

1. **全量 MVP（原方案）**：多个独立产品级能力同时交付。Good, because 覆盖面大；Bad, because 无法快速验证。否决。
2. **高血压垂直闭环（采纳）**：只交付一条完整用户路径，验证 Agent 核心价值。

## Decision Outcome

**Chosen option: 高血压垂直闭环**，0.0.1 只交付一条完整用户路径：

```text
知情同意与高血压建档
→ Agent 引导手工录入血压
→ 单位、范围和逻辑校验
→ 异常值二次确认（Agent 多轮追问闭环）
→ 七日趋势展示（Agent 分析总结）
→ 疑似紧急情况的保守就医提示
```

闭环必须以 Agent 决策循环（感知→思考→决策→行动→记忆）的形态交付。最小机件（会话级状态机、记忆注入、多轮确认、安全状态隔离、降级矩阵、流式输出）属于 0.0.1 横切硬性要求。

### 产品入口

1. `haven web`：启动患者端 Web/API（首个入口）
2. `haven check`：只读检查配置、数据库与安全规则
3. 旧 CLI REPL、飞书、Daemon 与通用任务入口不再继承；新入口须通过独立 ADR 评审

### 不在 0.0.1 内（保留为路线图）

自然语言健康数据抽取、用药提醒、通用医学知识问答、家庭协同、蓝牙设备、推送通知、报告、多智能体编排。

## Consequences

**Good:**
- 快速验证 Agent 核心价值
- P0 从此等同于 0.0.1 交付项

**Bad:**
- ADR-002 与 REQ-001/002/003 中超出闭环的原 P0 项被下调
- 其余能力仍保留在路线图（P1-P3），但不阻塞 0.0.1 交付
