# ADR-005：MVP 范围与项目入口

> **本文档是架构决策记录（ADR），记录"为什么 0.0.1 只做这个范围"。**
> **开发人员请直接阅读 [TRACEABILITY](../requirements/TRACEABILITY.md)，那里是 0.0.1 的权威交付清单。**
>
> 状态：已接受
> 日期：2026-09-01
> 依赖：ADR-001

## 背景

原需求把多个独立产品级能力同时列为 MVP，无法用一条用户路径快速验证产品价值；仓库当时也没有已实现的产品入口。

## 决策

**版本 `0.0.1` 只交付一条"高血压管理"的垂直闭环：**

```text
知情同意与高血压建档
→ Agent 引导手工录入血压
→ 单位、范围和逻辑校验
→ 异常值二次确认（Agent 多轮追问闭环）
→ 七日趋势展示（Agent 分析总结）
→ 疑似紧急情况的保守就医提示
```

**这条闭环必须以 Agent 决策循环（感知→思考→决策→行动→记忆）的形态交付**，而非"表单 + CRUD 接口 + 一段聊天文案"。构成闭环的最小机件（会话级状态机、记忆注入、多轮确认、安全状态按用户隔离、降级矩阵、流式输出）属于 0.0.1 横切硬性要求，见 [requirements/README 主路线](../requirements/README.md) 与 [TRACEABILITY 基线](../requirements/TRACEABILITY.md)。

### 产品入口

1. 首个入口为 `haven web`，启动患者端 Web/API。
2. 第二个入口为 `haven check`，只读检查配置、数据库与安全规则是否可用。
3. 入口实现前不在 `pyproject.toml` 声明命令，避免发布无效入口。
4. 旧 CLI REPL、飞书、Daemon 与通用任务入口不再继承；新入口须通过独立 ADR 评审。

### 不在 0.0.1 内（保留为路线图）

- 自然语言健康数据抽取（0.0.1 使用结构化表单 + 正则兜底）
- 用药提醒、漏服建议和药物相互作用
- 通用医学知识问答
- 家庭协同和多患者管理
- 蓝牙设备、推送通知、报告和多智能体编排

## 验收门槛

- 上述闭环的正常、非法输入、服务降级与安全路径均有自动化测试。
- 所有 P0 需求可追踪到验收标准与测试。
- 安全规则记录来源、版本、适用地区与生效日期。
- 未通过医学与隐私评审前，仅允许使用合成数据开发验证。

## 后果

此决策会下调 ADR-002 与 REQ-001/002/003 中超出闭环的原 P0 项。**P0 从此等同于 0.0.1 交付项**；其余能力仍保留在路线图（P1-P3），但不阻塞 0.0.1 交付。
