## 一、背景

ADR-002 定义了 12 大核心能力。现在反推：**支撑这些能力，底层需要哪些基础系统？**

反推是 Agent-First 方法论的落点：不做"万能框架"，只做"够用且可扩展的基座"。

## 二、决策

**支撑系统共 10 个，完整明细见 [REQ-002](../requirements/REQ-002-功能需求-系统基础能力.md)（S1-S10）。** 本文记录构成与核心取舍。

### 2.1 分层

```
Agent 能力层（F1-F12，面向用户） → 由基础系统层支撑
基础系统层（S1-S10）            → 依赖基础设施层（S10）
```

### 2.2 十大系统

| 系统 | 名称         | 职责（一句话）                                     |
| ---- | ------------ | -------------------------------------------------- |
| S9   | Agent 核心引擎 | **中枢**：感知→思考→决策→行动→记忆 的决策循环     |
| S1   | 记忆系统     | 用户画像、健康时间线、对话上下文、长期记忆         |
| S2   | 知识库       | 权威医学知识条目的存取与检索                       |
| S3   | 数据采集     | 自然语言/表单/校验/二次确认的输入通道              |
| S4   | 分析引擎     | 趋势、异常、达标率、风险（确定性计算优先）         |
| S5   | 通信系统     | 同步对话、异步推送、定时任务                       |
| S6   | 安全合规     | 输入/输出过滤、免责、审计、删除（横切）            |
| S7   | 个性化       | 沟通风格、知识水平、目标偏好适配                   |
| S8   | 会话管理     | 会话状态机与上下文（Agent 有状态闭环的前提）       |
| S10  | 基础设施     | 配置、日志、数据库、LLM 网关、异步框架             |

### 2.3 核心取舍

- **S9 是唯一中枢**：S1-S8、S10 都服务于 S9 的决策循环；能力层不直接操作基础系统。
- **S8 + S1 决定"是不是 Agent"**：会话级状态机（按用户隔离）+ 记忆注入上下文，是把交互从"请求-响应"提升为"有状态闭环"的关键。
- **确定性优先**：安全（S6）、校验（S3）、统计（S4）优先确定性代码，LLM 仅用于需要理解与生成的环节。

## 三、建设顺序

> 0.0.1 **只建设 ADR-005 垂直闭环实际需要的最小子集**，不按目录一次性搭建十个空系统。下表为长期建设顺序。

| 阶段    | 系统                                  |
| ------- | ------------------------------------- |
| Phase 1 | S10 · S9（核心循环）· S1 · S6 · S8 · S3（表单）· S4（趋势） |
| Phase 2 | S3（NL 解析）· S2 知识库 · S5 推送    |
| Phase 3 | S7 个性化 等增强系统                  |

## 四、后果

- 正面：系统间职责清晰、单向依赖、可分期建设。
- 风险：S9/S8/S1 若被绕开，产品会退化为"路由 + CRUD"；建设顺序须以 0.0.1 闭环为准（ADR-005）。
