# ADR-004：技术栈选型

- **Status**: Accepted (2026-09-01)
- **Deciders**: Haven 项目组
- **Date**: 2026-08-25
- **Depends on**: ADR-001, ADR-002, ADR-003

> **⚠️ 历史归档**：本文档记录 MDA 重写前的旧架构（FastAPI / 自建服务），
> 相关条目已废弃、不适用于当前版本；现行实现以 [README](../../README.md)
> 与代码为准。保留原文仅为决策溯源。

## Context

确定 Agent 定位与基础架构后，为各系统选择具体技术方案。核心原则：**简单优先，够用就好；为扩展留空间，但不过度设计。**

## Decision Drivers

- AI/LLM 生态成熟度
- 零运维起步，迁移路径清晰
- 生产可扩展

## Decision Outcome

**Chosen stack（历史）**: Python + FastAPI + SQLite（0.0.1）→ PostgreSQL（生产）+ LLM Gateway —— 已废弃：现行运行时为 managed-deepagents 0.6.1（`mda dev` / `mda deploy`），实际栈以 README 与 pyproject.toml 为准。

| 领域 | 选型 | 理由 |
|------|------|------|
| 语言/运行时 | Python ≥3.11（本地 dev 3.14、`mda build` 3.12） | AI/LLM 生态成熟；异步友好 |
| Web 框架 | ~~FastAPI~~（已废弃） | 仓库无自建 HTTP 服务；界面为 LangGraph Studio（`mda dev`） |
| 校验/配置 | Pydantic v2 / pydantic-settings | 与 FastAPI 无缝 |
| ORM/数据库 | SQLAlchemy（异步）+ SQLite → PostgreSQL | 零运维起步，迁移路径清晰 |
| LLM 接入 | ~~统一 LLM Gateway~~（已废弃） | 模型经 langchain-deepseek 直连；换模型只改 `.env` 的 `HAVEN_MODEL` |
| LLM 编排 | langchain 1.4 + deepagents 0.7（经 managed-deepagents 0.6.1） | langchain-core / langchain-openai 未采用；编排由 MDA 托管运行时提供 |
| 异步 | asyncio（stdlib） | 标准库即可 |
| 包管理 | uv | 快速、锁文件可复现（`uv.lock`） |
| 日志 | 平台侧日志（`mda logs`） | structlog 未接入；仓库内仅用标准库 logging |
| 定时任务 | APScheduler（远期） | 主动关怀/提醒阶段再引入 |
| 前端形态 | 无自研前端；LangGraph Studio / 外部通道（Slack） | 单页 Web / PWA 未实现 |
| 测试/质量 | 暂无测试与 CI | pytest/mypy/ruff 未接入；评测需 `mda evals init` 生成 |

> 现状对照：实际依赖（managed-deepagents==0.6.1 / langchain==1.4.0 / SQLAlchemy 2.0 /
> SQLite→PostgreSQL）以 pyproject.toml 与 README 为准；下表为历史选型记录。
> 「Considered Options」中的 LangGraph 条目亦为历史：现行 MDA 运行时即基于 LangGraph。

## Considered Options (不选的技术)

| 不选 | Good, because... | Bad, because... |
|------|-------------------|------------------|
| 重型编排框架（LangGraph 全量） | 功能完整 | 0.0.1 闭环不需复杂编排 |
| 分布式任务/缓存（Celery/Redis） | 生产成熟 | 单进程架构不需要 |
| 向量库（ChromaDB/Qdrant） | 检索能力强 | 0.0.1 无知识检索，Phase 2 再评估 |
| 时序库/图库/消息队列/gRPC/Django/K8s | 各自擅长领域 | 复杂度远超 MVP 需要 |

## Consequences

**Good:**
- 依赖少、启动快、零运维
- 升级路径明确（SQLite → PostgreSQL）

**Bad:**
- SQLite 并发写有上限（MVP 规模无碍）
- 技术选型是**既定基线**——若引入重型框架或更换核心栈，须新增 ADR 说明理由
