# ADR 索引 — 架构决策存档

> **本文档面向架构师 / PM。开发人员不需要阅读 ADR，请直接看 [requirements/](../requirements/README.md)。**

---

## 使用规则

1. **ADR 只记"为什么做这个决策"**：背景、决策、备选方案、权衡、后果。
2. **ADR 不维护需求明细**：能力清单、系统拆解、验收口径一律以 [requirements/](../requirements/) 为唯一来源，ADR 只做指向。禁止在 ADR 与 REQ 中同时维护同一份明细，否则必然漂移。
3. 新增/变更决策时新增或修订 ADR；**先写 ADR 再改需求**，反之必须同步注释原因。

## 状态约定

| 状态   | 含义                                         |
| ------ | -------------------------------------------- |
| 提议中 | 方案已提出，待评审                           |
| 已接受 | 方案通过评审，成为当前决策基线               |
| 已实现 | 决策已在代码中落地并通过验证                 |
| 已废弃 | 决策被否决或被其他 ADR 替代                  |

> 说明：2026-09 文档整理时，随"坚定 Agent 主路线"将 ADR-002/003/004 从"提议中"确认为基线（"已接受"）。0.0.1 的**实际交付范围仍以 ADR-005 与 TRACEABILITY 为准**，ADR-002/003 的能力/系统保留为产品路线图，不构成 0.0.1 交付承诺。
