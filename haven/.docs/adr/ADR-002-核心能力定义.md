# ADR-002：核心能力定义

- **Status**: Accepted (2026-09-01)
- **Deciders**: Haven 项目组
- **Date**: 2026-08-25
- **Depends on**: ADR-001

## Context

确定"个人慢病管理智能体"定位后，需明确 Agent 具备哪些面向用户的核心能力。采用 **Agent-First** 方法：先想象一个理想的慢病管理 Agent 会做什么，再反推需要什么支撑。

## Decision Drivers

- 能力必须有用户价值，可分期交付
- 必须体现 Agent 主动性（而非被动 Chatbot）
- 安全兜底是横切能力，约束所有其他能力

## Considered Options

1. **按功能模块划分 12 大能力（采纳）**：覆盖面完整，可分期交付。
2. **按技术栈划分**：过于技术视角，与用户价值脱节。否决。

## Decision Outcome

**Chosen option: 12 大核心能力模块**（原始需求文档 REQ-001 已归档，见 git 历史；F1-F12 明细见下表）。

| 模块 | 名称 | 职责 |
|------|------|------|
| C1（F1） | 健康画像管理 | 记住病史、过敏、用药等用户基本面 |
| C2（F2） | 体征追踪与分析 | 血压/血糖等体征的记录与趋势 |
| C3（F3） | 用药管理 | 用药方案、提醒、依从性 |
| C4（F4） | 症状记录追踪 | 症状录入、时间线、关联分析 |
| C5（F5） | 风险评估预警 | 基于指南的分层、预警与就医建议 |
| C6（F6） | 生活方式干预 | 饮食/运动/睡眠/目标的个性化引导 |
| C7（F7） | 医学知识问答 | 疾病/指标/药物知识的可靠解答 |
| C8（F8） | 情感支持陪伴 | 情绪识别、共情、危机转介 |
| C9（F9） | 复诊随访管理 | 复诊计划与提醒 |
| C10（F10） | 主动关怀 | 主动问候、提醒、阶段总结（Agent 主动性） |
| C11（F11） | 安全兜底 | 紧急识别、免责、审计、删除（横切能力） |
| C12（F12） | 家庭协同 | 家属授权查看与代管（远期） |

**关键取舍**：C11 安全兜底是横切能力，约束所有其它能力；C10 主动关怀体现 Agent 与被动 Chatbot 的本质差别。

### 阶段划分

> 0.0.1 实际交付范围已由 ADR-005 收敛，下表为产品路线图。

| 阶段 | 能力 | 理由 |
|------|------|------|
| Phase 1 | C1 画像 · C2 体征 · C11 安全兜底 | 0.0.1 高血压垂直闭环 |
| Phase 2 | C3 用药 · C4 症状 · C5 风险 · C7 问答 · C8 情感 · C10 主动 | 数据积累后逐步增强 |
| Phase 3 | C6 干预 · C9 复诊 · C12 家庭 | 依赖更丰富的知识与权限体系 |

## Consequences

**Good:**
- 能力边界清晰，每个能力有用户故事
- 可分期交付

**Bad:**
- 能力面大，须严格控制每个版本范围（ADR-005）
- 能力必须在 Agent 决策循环上实现，避免做成相互孤立的 CRUD 菜单
