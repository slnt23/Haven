# ADR-002：核心能力定义 — 从 Agent 视角出发

> **本文档是架构决策记录（ADR），记录"为什么选择这些能力"。**
> **开发人员请直接阅读 [REQ-001](../requirements/REQ-001-功能需求-用户端能力.md)，能力明细以 REQ-001 为唯一来源，本 ADR 不再展开。**
>
> 状态：已接受
> 日期：2026-08-25
> 接受日期：2026-09-01
> 依赖：ADR-001

---

## 一、背景

确定"个人慢病管理智能体"定位后，需明确 Agent 具备哪些面向用户的核心能力。这里采用 **Agent-First**：先想象一个理想的慢病管理 Agent 会做什么，再反推需要什么支撑。

## 二、决策

**Haven 的 Agent 能力分为 12 大模块，完整明细见 [REQ-001](../requirements/REQ-001-功能需求-用户端能力.md)（F1-F12）。** 本文只记录划分与取舍理由。

| 模块        | 名称           | 一句话职责                             |
| ----------- | -------------- | -------------------------------------- |
| C1（F1）    | 健康画像管理   | 记住病史、过敏、用药等用户基本面       |
| C2（F2）    | 体征追踪与分析 | 血压/血糖等体征的记录与趋势            |
| C3（F3）    | 用药管理       | 用药方案、提醒、依从性                 |
| C4（F4）    | 症状记录追踪   | 症状录入、时间线、关联分析             |
| C5（F5）    | 风险评估预警   | 基于指南的分层、预警与就医建议         |
| C6（F6）    | 生活方式干预   | 饮食/运动/睡眠/目标的个性化引导        |
| C7（F7）    | 医学知识问答   | 疾病/指标/药物知识的可靠解答           |
| C8（F8）    | 情感支持陪伴   | 情绪识别、共情、危机转介               |
| C9（F9）    | 复诊随访管理   | 复诊计划与提醒                         |
| C10（F10）  | 主动关怀       | 主动问候、提醒、阶段总结（Agent 主动性）|
| C11（F11）  | 安全兜底       | 紧急识别、免责、审计、删除（横切能力） |
| C12（F12）  | 家庭协同       | 家属授权查看与代管（远期）             |

**关键取舍**：C11 安全兜底是横切能力，约束所有其它能力；C10 主动关怀体现 Agent 与被动 Chatbot 的本质差别，是"主动行为"的主要载体。

## 三、优先级 / 阶段

> 0.0.1 的**实际交付范围已由 ADR-005 收敛**，下表为产品路线图划分，不代表 0.0.1 承诺。

| 阶段     | 能力                                   | 理由                                   |
| -------- | -------------------------------------- | -------------------------------------- |
| Phase 1  | C1 画像 · C2 体征 · C11 安全兜底       | 0.0.1 高血压垂直闭环（见 ADR-005）     |
| Phase 2  | C3 用药 · C4 症状 · C5 风险 · C7 问答 · C8 情感 · C10 主动 | 在数据积累后逐步增强 |
| Phase 3  | C6 干预 · C9 复诊 · C12 家庭           | 依赖更丰富的知识与权限体系             |

## 四、后果

- 正面：能力边界清晰、每个能力有用户故事、可分期交付。
- 风险：能力面大，必须严格控制每个版本范围（ADR-005）；能力必须在 Agent 决策循环上实现，避免做成相互孤立的 CRUD 菜单（见 [requirements/README](../requirements/README.md) 主路线）。
