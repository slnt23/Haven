# Haven 0.0.2 需求文档 — 健康建档与 Agent 引擎

> **目标：Agent 决策循环跑通，用户能完成知情同意和高血压建档。**
> 版本：0.0.2 · 状态：已确认 · 前提：0.0.1 已完成

---

## 0.0.2 交付目标

```text
隐私政策同意 → 引导建档（基本信息+疾病史）→ Agent 流式对话 → 画像确认
```

这是第一个有"Agent 感"的版本——用户不是填表单，而是在对话中被引导完成建档。

---

## 一、Agent 核心引擎（S9）★ 本版本中枢

```
用户输入 → S9.1 感知 → S9.2 思考 → S9.3 决策 → S9.4 行动 → S9.5 记忆
```

- [ ] **S9.1 感知：输入解析与意图识别**（部分）
  - 现状：紧急词扫描 + 命令路由由中间件确定性完成，其余意图由模型判断
  - **无延迟/准确率测量**（指标待补证据）

- [x] **S9.2 思考：上下文构建**
  - 组装：平台 system prompt + 记忆注入块（`middleware/memory_context.py`）+ 平台线程历史
  - 「60% 窗口」指标未测量

- [x] **S9.3 决策：多步推理与行动规划**
  - 确定性部分：命令路由 / 紧急拦截 / 工具参数校验；开放对话的推理由模型完成（无独立规划器）
  - 原则：安全优先 → 宁可多问不假设 → 确定性优先

- [ ] **S9.4 行动：响应生成**（部分）
  - 生成由模型完成；**SSE 由平台/Studio 展示，仓库无流式实现**
  - 安全场景的固定文案已实现（紧急/降级，`safety/`）

- [x] **S9.5 记忆：状态更新**
  - 现状：**只读注入，不写记忆**（记忆块每次由库内业务表确定性组装）；写入一律经工具落业务表

- [x] **S9.6 多轮对话管理**
  - 现状：「待确认项」由 `bp_pending_confirmations` / `onboarding_drafts` 持久化；话题跟踪由模型 + 平台线程历史承担

- [ ] **S9.7 流式响应**（不适用：由平台提供、仓库不可核对）

- [x] **S9.9 错误处理与降级**
  - DB 不可用：返回固定降级文案（`safety/degradation.py`），不谎报成功
  - 记忆注入失败：静默跳过（仅用当前上下文）
  - **无 LLM 故障分支**（模型故障为平台侧行为）

- [x] **S9.10 安全边界** — 所有 LLM 回复过安全过滤器；不做诊断性表述；不提供个性化用药建议

### Agent 闭环基线（本版本交付的）

| # | 机件 | 要求 |
| - | ---- | ---- |
| B1 | 会话级状态机 | 按用户/会话隔离，禁止全局单例共享状态 |
| B2 | 记忆注入上下文 | "思考"前读取用户画像注入决策上下文 |
| B3 | 多轮确认闭环 | 建档引导为"可续接"对话状态流 |
| B4 | 安全状态按用户隔离 | 紧急/降级只作用于当前用户 |
| B6 | 流式输出 | SSE 逐 token 输出 |

> 现状注记：B1/B4 由平台持久线程与逐条判定承担（无自建状态机）；B6 流式由平台/Studio 提供，仓库无实现。

## 三、健康建档（F1）

- [x] **F1.1 基础信息采集**
  - 采集项：出生日期（1900-01-01~今天）、性别、身高（80-250cm）、体重（2-500kg）、称呼（nickname ≤20字，可跳过）；年龄由出生日期推导
  - 方式：Agent 引导式对话 → 逐项询问 → 确认汇总
  - nickname 是档案数据，不是身份（ADR-006 单租户模型）

- [x] **F1.2 疾病史记录**
  - 录入已确诊疾病：名称、确诊时间、严重程度（轻度/中度/重度）
  - 疾病名仅支持精确匹配「高血压」（**无 ICD-10**）；其他病名提示「0.0.1 版本仅支持登记高血压」

- [ ] **S1.3 对话记忆窗口**（不适用）— 历史由平台线程承担，无 20 轮窗口/摘要逻辑
- [x] **S1.6 记忆检索** — `middleware/memory_context.py` 只读组装（档案/疾病/近 7 天血压/待确认/建档草稿）；延迟指标未测量
- [ ] **S1.7 记忆更新**（**取消**）— 与现行只读注入设计相反：记忆块不落库、不写回；数据写入只经工具
