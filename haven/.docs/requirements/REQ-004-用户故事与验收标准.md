# REQ-004：用户故事与验收标准

> 状态：开发标准
> 版本：0.0.1

---

## 说明

本文件包含产品路线图故事。`0.0.1` 的发布故事及异常路径以 [TRACEABILITY.md](TRACEABILITY.md) 为准。

本文档将 Agent 能力定义转化为可测试的用户故事，每个故事包含：

- **用户故事**：As a / I want / So that 格式
- **验收标准**：可验证的 Acceptance Criteria
- **优先级**：**P0 = 0.0.1 交付故事**（须与 TRACEABILITY 一一对应）/ P1、P2 = 路线图

---

## 场景一：新用户首次使用

### US-001：新用户注册与建档

- **优先级**：P0
- **用户故事**：作为新确诊的高血压患者，我希望在首次使用时通过引导完成健康建档，让 Agent 了解我的基本健康状况。
- **验收标准**：
  - [ ] 用户首次打开应用时，看到欢迎页面和隐私政策
  - [ ] 用户同意隐私政策后，进入引导式建档流程
  - [ ] 建档流程包含：基本信息（年龄/性别/身高/体重）→ 疾病史（已确诊慢病，如高血压）→ 生成画像摘要
  - [ ] 用药方案、过敏史等其余画像字段属路线图（F1.3/F1.4），0.0.1 不采集
  - [ ] 用户可跳过非必填项（家族史、生活习惯，路线图字段）
  - [ ] 建档完成后，Agent 生成健康画像摘要并请用户确认
  - [ ] 用户确认后，画像保存并可随时修改
  - [ ] 整个建档流程在 5 分钟内完成

### US-002：通过对话补充健康信息

- **优先级**：P1
- **用户故事**：作为慢病患者，我希望在日常对话中自然补充健康信息，而不是每次都填表单。
- **验收标准**：
  - [ ] 用户说"我最近开始吃阿托伐他汀了"，Agent 识别出新的用药信息并询问详情
  - [ ] 用户说"我爸也有高血压"，Agent 记录家族史信息
  - [ ] Agent 在更新画像前会向用户确认："我更新了您的用药方案，确认一下？"
  - [ ] 用户可拒绝更新，画像保持不变

## 场景二：日常体征管理

### US-003：每日血压记录

- **优先级**：P0
- **用户故事**：作为高血压患者，我希望每天方便地记录血压值，让 Agent 帮我追踪变化趋势。
- **验收标准**：
  - [ ] 用户输入"今天血压 135/85"，Agent 正确提取收缩压 135、舒张压 85
  - [ ] 用户输入"高压 150，低压 95"，Agent 同样正确解析
  - [ ] 记录成功后，Agent 回复包含当前值、与目标的对比、简短评价
  - [ ] 异常值（如收缩压 >180）触发二次确认："这个数值偏高，确认无误吗？"
  - [ ] 用户可通过表单精确录入（选择收缩压/舒张压滑动条）

### US-004：查看血压趋势（0.0.1：七日趋势）

- **优先级**：P0
- **用户故事**：作为高血压患者，我想查看近一周血压变化趋势，了解控制效果。
- **验收标准（0.0.1）**：
  - [ ] 用户问"最近一周血压怎么样"，Agent 展示**七日趋势总结**
  - [ ] 总结包含：平均值、最高/最低值、达标率、变化方向
  - [ ] 总结由 Agent 基于确定性统计（REQ-002 S4.1）生成解读，并可结合用户近期记录
- **路线图（P1）**：折线图（目标范围标注 + 异常高亮）、周/月/季度视图切换

### US-005：血糖记录与趋势

- **优先级**：P1
- **用户故事**：作为糖尿病患者，我希望能记录空腹和餐后血糖，追踪血糖控制情况。
- **验收标准**：
  - [ ] 用户输入"空腹血糖 6.2"，Agent 正确记录类型和数值
  - [ ] 用户输入"午餐后血糖 9.8"，Agent 正确记录
  - [ ] Agent 能区分空腹/餐后/随机血糖
  - [ ] 血糖趋势分析包含空腹和餐后两条线

## 场景三：用药管理

### US-006：收到用药提醒并确认

- **优先级**：P1
- **用户故事**：作为需要每天吃降压药的患者，我希望在服药时间收到提醒，并能一键确认已服药。
- **验收标准**：
  - [ ] 到达设定的服药时间，用户收到推送通知
  - [ ] 通知内容包含药品名称和剂量："该吃降压药了，氨氯地平 5mg"
  - [ ] 用户点击通知进入应用，看到"已服用"和"稍后提醒"两个按钮
  - [ ] 点击"已服用"后，系统记录服药时间并回复鼓励语
  - [ ] 点击"稍后提醒"后，15 分钟后再次提醒
  - [ ] 如果用户未响应，30 分钟后再次提醒（最多 3 次）

### US-007：查看服药记录

- **优先级**：P1
- **用户故事**：作为慢病患者，我想查看近期的服药情况，了解自己有没有漏服。
- **验收标准**：
  - [ ] 用户问"这周有没有漏吃药"，Agent 展示服药统计
  - [ ] 统计包含：应服次数、实际服用次数、漏服次数、依从率
  - [ ] 用户可查看具体某天的服药详情
  - [ ] 漏服日期被高亮标注

### US-008：漏服处理建议

- **优先级**：P1
- **用户故事**：作为患者，当我漏服药物时，希望 Agent 告诉我应该补服还是跳过。
- **验收标准**：
  - [ ] 用户问"我忘记吃早上的降压药了，现在要不要补？"，Agent 给出建议
  - [ ] 建议基于漏服时间间隔和药品特性
  - [ ] 建议附带免责声明："以上建议仅供参考，请咨询医生"
  - [ ] 对于不确定的情况，Agent 建议咨询医生

## 场景四：知识问答

### US-009：了解疾病知识

- **优先级**：P1
- **用户故事**：作为新确诊糖尿病患者，我有很多关于疾病的问题，希望 Agent 能用通俗的语言解释。
- **验收标准**：
  - [ ] 用户问"糖尿病是什么"，Agent 给出通俗易懂的解释
  - [ ] 解释包含：病因、类型、主要症状、为什么需要控制血糖
  - [ ] 回答末尾附带信息来源和免责声明
  - [ ] 用户追问"糖尿病有什么并发症"，Agent 能基于上下文回答

### US-010：解读检查指标

- **优先级**：P1
- **用户故事**：作为患者，我拿到化验单后想了解指标的含义，希望 Agent 帮我解读。
- **验收标准**：
  - [ ] 用户输入"糖化血红蛋白 7.2% 正常吗"，Agent 给出解读
  - [ ] 解读包含：正常范围、当前值的含义、与目标的差距
  - [ ] Agent 说明"糖化血红蛋白反映的是近 2-3 个月的平均血糖水平"
  - [ ] 回答不提供诊断结论，附带免责声明

### US-011：了解药物信息

- **优先级**：P1
- **用户故事**：作为患者，我换了新药后想了解这个药的副作用和注意事项。
- **验收标准**：
  - [ ] 用户问"氨氯地平有什么副作用"，Agent 列出常见副作用
  - [ ] 回答包含：作用机制、常见副作用、注意事项、禁忌
  - [ ] Agent 不回答"我应该吃多少剂量"等个性化用药建议
  - [ ] 回答附带信息来源和免责声明

## 场景五：风险评估

### US-012：了解当前风险等级

- **优先级**：P1
- **用户故事**：作为高血压患者，我想知道当前血压控制得怎么样，有没有风险。
- **验收标准**：
  - [ ] 用户问"我血压控制得怎么样"，Agent 基于近期数据给出评估
  - [ ] 评估包含：当前血压分级（正常/正常高值/1级/2级/3级）
  - [ ] 如果数据不足（如最近 7 天没有记录），Agent 提醒用户先记录
  - [ ] 评估附带免责声明和就医建议

### US-013：紧急情况响应

- **优先级**：P0
- **用户故事**：作为可能处于紧急情况的用户，我需要系统立即给出保守且不会延误线下急救的指引。
- **验收标准**：
  - [ ] 用户输入"我胸口疼得厉害"，Agent 立即触发紧急响应
  - [ ] 中国地区紧急响应明确建议立即拨打 120 或前往最近急诊；其他地区使用配置的本地号码
  - [ ] 系统进入安全状态，只允许与立即求助相关的最小交互，不继续诊断或常规健康建议
  - [ ] 否定句、他人转述和边界体征不会仅因单个关键词被直接判定为确定事件
  - [ ] 事件以最小必要字段记录规则版本、触发原因和结果，不复制完整用户输入

## 场景六：情感陪伴

### US-014：情绪支持

- **优先级**：P1
- **用户故事**：作为慢病患者，当我对病情感到焦虑时，希望有人能理解我的感受并给我鼓励。
- **验收标准**：
  - [ ] 用户说"最近血压老是控制不好，很烦"，Agent 识别到负面情绪
  - [ ] Agent 给予共情回应："血压波动确实让人焦虑，很多患者都有这样的感受"
  - [ ] Agent 温和鼓励并给出建设性建议："我们一起看看最近的数据，找找可能的原因"
  - [ ] Agent 不轻视用户的感受（不说"没事的"、"别担心"等敷衍话）

### US-015：健康行为鼓励

- **优先级**：P1
- **用户故事**：作为患者，当我坚持健康行为时，希望得到肯定和鼓励，增强我的动力。
- **验收标准**：
  - [ ] 用户连续 7 天按时服药，Agent 主动给予肯定
  - [ ] 用户血压连续一周达标，Agent 给予鼓励
  - [ ] 鼓励语具体而有诚意："这周血压全部达标，您的坚持见效了！"
  - [ ] 不夸大或虚假鼓励

## 场景七：主动关怀

### US-016：每日问候与提醒

- **优先级**：P1
- **用户故事**：作为慢病患者，我希望 Agent 能主动关心我，提醒我按时测量和服药。
- **验收标准**：
  - [ ] 在用户设定的时间收到每日问候
  - [ ] 问候内容包含当日天气和健康提醒
  - [ ] 如果用户当天未记录体征，中午收到提醒
  - [ ] 用户可回复"今天不想记录"，Agent 不再提醒
  - [ ] 每日推送不超过 5 条

### US-017：阶段性健康报告

- **优先级**：P2
- **用户故事**：作为慢病患者，我想定期收到健康总结，了解自己的整体状况。
- **验收标准**：
  - [ ] 每周一自动推送上周健康周报
  - [ ] 周报包含：体征趋势、达标率、服药依从性、关键变化
  - [ ] 周报语言简洁易懂，不使用医学术语
  - [ ] 用户可查看和下载历史周报

## 场景八：症状追踪

### US-018：记录身体不适

- **优先级**：P1
- **用户故事**：作为慢病患者，我有时会感到不适，希望记录下来方便后续和医生沟通。
- **验收标准**：
  - [ ] 用户说"这两天头晕，特别是早上起床的时候"，Agent 记录症状
  - [ ] Agent 追问严重程度（1-5 级）和持续时间
  - [ ] 记录成功后，Agent 说"已记录，下次复诊时可以给医生看"
  - [ ] 用户可以查看症状时间线

### US-019：症状与体征关联

- **优先级**：P2
- **用户故事**：作为患者，我想知道不舒服的时候是不是和血压波动有关。
- **验收标准**：
  - [ ] 用户问"我头晕的时候血压是不是都偏高"，Agent 分析关联
  - [ ] Agent 展示症状时的血压数据对比
  - [ ] 回答附带免责声明

## 场景九：复诊管理

### US-020：复诊提醒

- **优先级**：P2
- **用户故事**：作为慢病患者，我希望 Agent 提醒我按时复诊，不要错过。
- **验收标准**：
  - [ ] 用户录入复诊计划后，提前 3 天收到提醒
  - [ ] 提醒包含：复诊日期、科室、准备事项
  - [ ] 复诊前 1 天再次提醒
  - [ ] 用户确认已复诊后，可录入医生的新建议

## 场景十：安全与隐私

### US-021：数据隐私控制

- **优先级**：P0
- **用户故事**：作为用户，我希望我的健康数据是安全的，并且我能控制自己的数据。
- **验收标准**：
  - [ ] 用户可在设置中查看隐私政策
  - [ ] 用户可导出所有健康数据（CSV 格式）
  - [ ] 用户可请求删除所有数据，30 天内完成
  - [ ] 删除请求需要二次确认，防止误操作

### US-022：识别超出范围的问题

- **优先级**：P0
- **用户故事**：作为系统，当用户提出超出慢病管理范围的问题时，我应该引导正确渠道。
- **验收标准**：
  - [ ] 用户问"我这是什么病"，Agent 回答"我无法提供诊断，建议您去医院就诊"
  - [ ] 用户问"我应该吃什么药"，Agent 回答"用药方案需要医生制定，建议咨询医生"
  - [ ] 用户描述急性症状，Agent 引导立即就医

## 场景十一：0.0.1 异常与降级路径

### US-023：非法体征输入

- **优先级**：P0
- **验收标准**：单位缺失、收缩压不大于舒张压、未来测量时间或超出支持范围时不直接入库，并以易懂语言提示修正。

### US-024：异常值二次确认

- **优先级**：P0
- **验收标准**：异常但可记录的血压值在保存前显示数值、单位和时间供用户确认；拒绝后不产生体征记录。

### US-025：重复提交

- **优先级**：P0
- **验收标准**：同一请求重试不会生成重复记录；系统返回原记录结果或明确提示冲突。

### US-026：服务降级

- **优先级**：P0
- **验收标准**：LLM 不可用不影响手工录入、规则校验和趋势查询；数据库不可用时不宣称保存成功，并提供可重试提示。

### US-027：撤回同意

- **优先级**：P0
- **验收标准**：用户撤回健康数据处理同意后停止新增采集，并可进入导出或删除流程；系统记录同意版本与撤回时间。

### US-028：紧急识别测试边界

- **优先级**：P0
- **验收标准**：安全测试集覆盖明确症状、否定、转述、错别字、含糊描述和阈值边界，并分别报告误报与漏报结果。
