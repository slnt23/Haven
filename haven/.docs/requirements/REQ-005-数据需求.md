### D15：同意记录（ConsentRecord）

记录隐私政策版本、处理目的、同意范围、是否单独同意、同意/撤回时间和采集入口。同意记录采用追加写，撤回产生新事件而不覆盖历史事实。

### D16：安全事件（SafetyEvent）

记录事件 ID、去标识主体引用、触发规则及版本、触发原因、风险级别、用户所在地区、响应模板版本、处理结果和时间；默认不保存完整输入。

### D17：通知及送达尝试（NotificationDelivery）

记录通知类型、计划时间、实际发送时间、渠道、幂等键、送达状态、重试次数和用户确认。该实体在提醒功能进入开发阶段后启用。

### D18：授权关系（CaregiverAuthorization）

记录患者与家属的授权范围、生效/失效时间和撤回状态。家庭协同不得仅依赖共享 `user_id`。

### D19：数据权利请求（DataSubjectRequest）

记录查阅、更正、导出、删除请求的范围、身份验证状态、处理期限、完成时间和结果证明。

### D20：规则版本（SafetyRuleVersion）

记录规则内容摘要、来源定位、适用地区/人群、版本、生效/失效日期、医学审核状态及测试集版本。

## 三、数据存储策略

### 3.1 存储分层

| 数据层   | 存储引擎         | 数据内容                              | 加密                       |
| -------- | ---------------- | ------------------------------------- | -------------------------- |
| 热数据   | 内存             | 当前请求所需的最小会话上下文          | 进程隔离，禁止落入调试日志 |
| 温数据   | SQLite           | 用户画像、用药方案、近 3 个月健康数据 | AES-256                    |
| 冷数据   | SQLite           | 3 个月前的健康数据、历史会话摘要      | AES-256                    |
| 审计数据 | SQLite（独立表） | 审计日志                              | 部分字段加密               |

### 3.2 数据生命周期

```
创建 → 活跃使用 → 归档 → 删除
  │        │         │       │
  │        │         │       └── 用户请求删除 / 账号注销
  │        │         └────────── 超过 12 个月的对话记录
  │        └──────────────────── 日常读写
  └───────────────────────────── 用户录入
```

### 3.3 数据保留策略

| 数据类型 | 默认保留期     | 用户可删除 | 说明                                              |
| -------- | -------------- | ---------- | ------------------------------------------------- |
| 用户画像 | 永久（活跃期） | 是         | 销户时全部删除                                    |
| 健康数据 | 永久（活跃期） | 是         | 体征、用药、症状记录                              |
| 对话记录 | 12 个月        | 是         | 可提前删除                                        |
| 审计日志 | 按处理目的确定 | 受限       | 删除后保留项须去标识化并记录依据                  |
| 会话摘要 | 永久（活跃期） | 是         | 与画像同步删除                                    |
| 血压待确认态 | 24 小时    | 是         | 过期即失效，下次触达时清除                        |
| 建档草稿 | 完成或取消即删 | 是         | 未完成时仅 7 天内参与记忆注入（超过不再注入，行仍保留） |

## 四、数据隐私与安全

### 4.1 敏感数据分级

| 级别       | 数据内容                           | 保护措施                   |
| ---------- | ---------------------------------- | -------------------------- |
| **高敏感** | 密码哈希、手机号、身份证号         | bcrypt 哈希 / AES-256 加密 |
| **中敏感** | 健康数据（体征、疾病、用药、症状） | AES-256 加密存储           |
| **低敏感** | 非健康类界面偏好                   | 数据库级访问控制           |
| **公开**   | 知识库内容、免责声明模板           | 明文存储                   |

### 4.2 数据脱敏规则

| 场景     | 脱敏方式                       |
| -------- | ------------------------------ |
| 日志输出 | 自动过滤姓名、手机号、身份证号 |
| 数据分析 | 去标识化处理                   |
| 数据导出 | 用户可选脱敏导出               |
| 开发测试 | 使用合成数据，禁止使用真实数据 |

### 4.3 数据访问控制

- 所有数据访问必须通过 user_id 隔离
- API 层面验证 JWT Token 中的 user_id 与请求数据的所有者一致
- 数据库层面不直接暴露，通过 ORM 层加 user_id 过滤条件
- 家属访问必须检查独立授权记录的范围、状态和有效期
- 撤回同意后，采集入口必须在服务端拒绝写入，不能只依赖前端隐藏

## 五、数据迁移策略

### 5.1 版本管理

- 使用 Alembic 管理数据库 schema 迁移
- 每次 schema 变更生成独立的 migration 脚本
- Migration 脚本支持 upgrade 和 downgrade

### 5.2 SQLite → PostgreSQL 迁移路径

```
Phase 1 (MVP): SQLite 单文件
Phase 2: SQLAlchemy 抽象层已就绪，切换连接字符串
Phase 3: 数据迁移脚本 + 验证
```

### 5.3 数据备份

- MVP 阶段：每日定时备份 SQLite 文件
- 生产阶段：PostgreSQL 主从复制 + 定期全量备份
