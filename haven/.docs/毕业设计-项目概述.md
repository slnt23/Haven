# 本科毕业设计课题

## 题目

**面向慢病患者的个人健康管理智能体系统设计与实现**

_Design and Implementation of a Personal AI Agent for Chronic Disease Management_

---

## 一、项目背景与问题

中国已确诊慢病（高血压、糖尿病等）患者基数庞大，以 40–70 岁中老年群体为主。这部分患者在两次门诊之间长期处于"无人管理"的健康空白期：医生做的是"关键时刻的决策"，而在日常生活中缺乏一个持续陪伴、持续追踪的角色。

本项目的出发点正是填补这个空白——用 AI Agent 承担"日常时刻的陪伴与管理"。

产品定位明确：**不是医疗诊断工具，不是在线问诊平台，也不是通用 Chatbot**，而是一个能长期陪伴慢病患者的个人健康管理智能体。

---

## 二、核心思路：从"工具"到"伙伴"

### 2.1 不是被动问答，而是主动陪伴

与普通 Chatbot 的本质区别在于"主动性"：

- Chatbot：用户问 → 系统答，问完即止
- Agent：用户建档 → 持续追踪 → 主动问候 → 识别异常 → 安全提醒

Agent 知道用户是谁、有什么病史、最近血压趋势如何、什么时候该测血压了——它像一个有记忆、有判断力的健康伙伴，而非一次性查询工具。

### 2.2 从屏幕后走到用户身边

当前 MVP 为文本对话形态，但长期方向是走向**物理实体**——通过一个始终在线的语音终端，让慢病老人只需开口说话就能获得陪伴。终端不只是一个"能说话的音箱"，更是一个能主动定期安全巡检的守护者：

> "您今天感觉怎么样？血压测了吗？"
> → 用户回应 → 正常对话
> → 超时无响应 → 升级通知家属

### 2.3 多设备生态融入用户生活（远期想法）

不强迫用户购买新设备或学习新操作。智能体搭载策略以用户已有的设备为起点：

- **随身层**：手机、手表、智能拐杖/轮椅（用户本来就带着的）
- **居家层**：自有语音终端、电视、平板
- **联动层**：血压计、血糖仪、智能药盒等（不搭载 Agent，但提供感知数据）

核心引擎保持设备无关，每类设备通过适配层接入，用户可根据自身条件自由组合。

## 三、核心能力

| 能力           | 要解决的问题                                      |
| -------------- | ------------------------------------------------- |
| 健康画像管理   | Agent 记住用户的基本面：病史、过敏、用药          |
| 体征追踪与分析 | 血压/血糖等体征的持续记录与趋势解读               |
| 用药管理       | 方案记录、提醒、依从性追踪                        |
| 风险评估预警   | 基于指南的分层、预警与就医建议                    |
| 主动关怀       | 主动问候、定期查看（Agent 与 Chatbot 的本质区别） |
| 安全兜底       | 紧急识别、免责声明、数据删除（横切于所有能力）    |

---

## 四、技术路线概要

- **智能体框架**：基于 LangGraph 的决策循环（感知 → 思考 → 决策 → 行动 → 记忆），Agent 编排通过 managed-deepagents 托管运行时
- **LLM 模型**：大语言模型负责自然语言理解与生成，安全相关判断走确定性代码
- **数据层**：SQLite（开发）→ PostgreSQL（部署），ORM 抽象保证可替换
- **语音交互**（远期）：本地唤醒词检测（隐私不泄漏） + 云端 ASR/TTS，Wi-Fi/WebSocket 全双工通信
- **硬件**（远期）：树莓派级单板计算机（成本 ¥200–400），麦克风阵列 + 扬声器 + 物理按钮
