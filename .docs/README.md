## 项目定位

Haven 重新定位为**面向患者端的长期陪伴型慢病管理智能体**，能够长期陪伴一个用户，理解用户健康状态，帮助管理疾病风险。

这不是一个普通的 Chatbot，而是 **Personal Chronic Disease Management Agent（个人慢病管理智能体）**。

## 需求管理

ADR-005 是 `0.0.1` 范围的权威来源。路线图文档中的 P0 若未进入[追踪矩阵](requirements/TRACEABILITY.md)，不得视为 `0.0.1` 发布门槛。

| 优先级 | 含义         | 说明                       |
| ------ | ------------ | -------------------------- |
| P0     | 当前版本必须 | 缺失时当前版本不可交付     |
| P1     | 下一阶段重要 | 当前闭环稳定后优先实现     |
| P2     | 后续增强     | 有明确价值但不进入近期版本 |
| P3     | 未来探索     | 尚需验证的方向性需求       |

| 状态   | 含义                         |
| ------ | ---------------------------- |
| 草案   | 需求已提出，尚未成为交付承诺 |
| 已确认 | 已进入对应版本范围和追踪矩阵 |
| 开发中 | 正在实现                     |
| 已实现 | 实现及测试均已完成           |
| 已废弃 | 已取消或被其他需求替代       |

P0 需求必须具备稳定 ID、前置条件、输入边界、正常与异常流程、可观察验收结果、安全/隐私影响、依赖需求及对应自动化测试。仅写“系统应支持”或示例，不视为可交付需求。

统一条目模板：

```text
ID / 目标 / 优先级 / 前置条件
输入与数据约束
正常流程
异常与降级流程
验收标准
安全与隐私影响
依赖需求 / 对应测试
```

## 设计方法论

本项目采用 **Agent-First（智能体优先）** 的设计方法论：

```
定义 Agent → 反推能力 → 确定架构 → 选择技术栈
```

先明确 Agent 要做什么、为谁服务，再反推需要什么底层能力，最后选择技术方案。每一层架构都有明确的业务价值来源，避免过度设计。
