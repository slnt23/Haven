# REQ-002：功能需求 — 系统基础能力

> 状态：开发标准
> 版本：0.0.1

---

## 需求清单总览

本文件描述支撑 Agent 运行所需的底层系统。`0.0.1` 只实现 Agent 闭环（主路线基线）直接依赖的子集，以 [TRACEABILITY.md](TRACEABILITY.md) 为准。

> **优先级口径：P0 = 0.0.1 交付项**（见 [README](README.md)）。标 P0 的条目是 0.0.1 必须具备的支撑系统（含 Agent 闭环机件）；其余为路线图，勿提前实现。

**S9（Agent 核心引擎）是项目最核心的系统，定义了 Agent 如何感知、思考、决策、行动。所有其他系统（S1-S8、S10）都是为 S9 服务的。**

| 编号   | 系统模块           | 需求数 | 角色                                        |
| ------ | ------------------ | ------ | ------------------------------------------- |
| **S9** | **Agent 核心引擎** | **10** | **★ 核心：Agent 决策循环，所有能力的中枢**  |
| S1     | 记忆系统           | 8      | 为 Agent 提供用户画像、历史数据、对话上下文 |
| S2     | 知识库             | 6      | 为 Agent 提供医学知识支撑                   |
| S3     | 数据采集           | 6      | 为 Agent 提供结构化的健康数据输入           |
| S4     | 分析引擎           | 6      | 为 Agent 提供趋势分析、异常检测、风险评估   |
| S5     | 通信系统           | 6      | Agent 主动推送、提醒的通道                  |
| S6     | 安全合规           | 8      | Agent 所有输出的安全兜底                    |
| S7     | 个性化             | 5      | Agent 根据用户特征调整行为                  |
| S8     | 会话管理           | 5      | Agent 多轮对话的上下文管理                  |
| S10    | 基础设施           | 8      | 配置、日志、数据库、LLM 网关                |

## S1：记忆系统（Memory System）

### S1.1 用户画像存储

- **优先级**：P0
- **描述**：系统应持久化存储用户的结构化健康画像数据
- **数据**：基础信息、疾病史、用药方案、过敏史、家族史、生活习惯
- **存储**：关系型数据库表，字段明确、可索引
- **约束**：所有修改操作需记录时间戳和版本

### S1.2 健康时间线存储

- **优先级**：P0
- **描述**：系统应按时间顺序存储所有健康事件记录
- **数据**：体征记录、用药记录、症状记录、复诊记录
- **存储**：时序表，支持按用户+时间范围查询
- **约束**：写入性能需支持每秒 10+ 条记录

### S1.3 对话记忆窗口

- **优先级**：P0
- **描述**：系统应缓存最近 N 轮对话历史用于当前会话上下文
- **参数**：默认 N=20 轮，可配置
- **存储**：内存缓存
- **约束**：超出窗口的对话自动做摘要压缩

### S1.4 对话摘要压缩

- **优先级**：P1
- **描述**：系统应将超出窗口的早期对话压缩为摘要
- **输入**：超出窗口的对话历史
- **输出**：关键信息摘要（健康相关要点、用户偏好）
- **实现**：LLM 生成摘要

### S1.5 长期记忆存储

- **优先级**：P2
- **描述**：系统应存储关键健康事件和重要对话摘要作为长期记忆
- **内容**：诊断变更、用药方案变更、重大健康事件、用户偏好
- **存储**：结构化存储 + 向量索引（Phase 2）
- **约束**：需支持遗忘/降权机制

### S1.6 记忆检索

- **优先级**：P0
- **描述**：系统应能根据当前对话上下文检索相关记忆
- **检索维度**：用户画像、近期健康事件、相关历史对话摘要
- **约束**：检索延迟 < 200ms

### S1.7 记忆更新

- **优先级**：P0
- **描述**：系统应在对话结束后自动更新相关记忆
- **触发**：每轮对话结束后
- **内容**：新增的健康数据、更新的画像信息、新的事件记录

### S1.8 记忆隔离

- **优先级**：P0
- **描述**：不同用户的记忆数据必须严格隔离
- **约束**：任何情况下不得出现跨用户数据泄露

## S2：知识库（Knowledge Base）

### S2.1 疾病知识存储

- **优先级**：P1
- **描述**：系统应存储常见慢病的结构化知识
- **覆盖**：高血压、糖尿病、高血脂、COPD、冠心病、脑卒中、慢性肾病
- **格式**：Markdown + YAML Frontmatter，包含疾病概述、病因、症状、诊断标准、治疗原则、并发症
- **约束**：知识来源必须是权威临床指南和教科书

### S2.2 药物知识存储

- **优先级**：P1
- **描述**：系统应存储常用慢病药物的结构化知识
- **覆盖**：降压药、降糖药、降脂药、抗凝药等大类
- **格式**：Markdown + YAML Frontmatter，包含通用名、商品名、作用机制、用法用量、副作用、禁忌
- **约束**：知识来源必须是药品说明书和药典

### S2.3 检查指标知识存储

- **优先级**：P1
- **描述**：系统应存储常见检查指标的参考范围和解读
- **覆盖**：血常规、生化全项、尿常规、糖化血红蛋白、血脂等
- **格式**：Markdown + YAML Frontmatter

### S2.4 知识检索

- **优先级**：P1
- **描述**：系统应能根据用户查询检索相关知识条目
- **检索方式**：关键词匹配（P0） + 语义检索（P1）
- **约束**：检索延迟 < 500ms，Top-K 结果不超过 5 条

### S2.5 知识更新机制

- **优先级**：P1
- **描述**：系统应支持知识库的版本化更新
- **方式**：文件替换 + 版本号管理
- **约束**：更新不中断服务（热加载）

### S2.6 知识来源追溯

- **优先级**：P1
- **描述**：每条知识条目应标注来源和更新时间
- **输出**：在回答中附带知识来源引用
- **约束**：增强可信度和可审计性

## S3：数据采集系统（Data Collection）

### S3.1 自然语言数据提取

- **优先级**：P1
- **描述**：系统应能从用户自然语言中提取结构化的健康数据（0.0.1 不做，见 README 第五节）
- **输入**：自由文本
- **输出**：{数据类型, 数值, 单位, 时间戳, 置信度}
- **实现**：LLM Function Calling 提取
- **约束**：置信度 < 0.7 时需二次确认

### S3.2 结构化表单录入

- **优先级**：P0
- **描述**：系统应提供结构化的数据录入表单
- **支持类型**：体征录入、用药录入、症状录入
- **约束**：表单字段带实时校验

### S3.3 数据校验

- **优先级**：P0
- **描述**：系统应对所有录入的健康数据进行校验
- **校验规则**：数值范围、逻辑一致性、格式正确性
- **输出**：校验通过 / 校验失败 + 错误提示

### S3.4 异常值二次确认

- **优先级**：P0
- **描述**：系统应在检测到异常数据时要求用户二次确认
- **示例**："您输入的收缩压是 200mmHg，这个数值偏高，确认无误吗？"

### S3.5 快捷录入

- **优先级**：P1
- **描述**：系统应提供快捷按钮和预设选项减少用户输入负担
- **示例**：服药确认"已服用"按钮、症状类型快捷选择

### S3.6 数据导入导出

- **优先级**：P2
- **描述**：系统应支持用户导出健康数据（CSV/PDF）和导入历史数据
- **约束**：导出数据需脱敏处理（可选）

## S4：分析引擎（Analysis Engine）

### S4.1 趋势分析

- **优先级**：P0
- **描述**：系统应计算体征数据的趋势指标（0.0.1 交付血压七日趋势总结）
- **指标**：移动平均、变化率、变化方向（上升/下降/稳定）
- **实现**：纯统计计算，不依赖 LLM

### S4.2 异常检测

- **优先级**：P0
- **描述**：系统应基于规则引擎检测异常体征值
- **规则**：基于临床指南的阈值（如血压 ≥140/90）
- **输出**：异常等级（正常/偏高/偏低/严重异常）
- **实现**：纯规则计算，不依赖 LLM

### S4.3 达标率计算

- **优先级**：P1
- **描述**：系统应计算体征数据在目标范围内的比例
- **输出**：周达标率、月达标率、不达标天数

### S4.4 风险评估

- **优先级**：P1
- **描述**：系统应基于指南分层规则进行风险评估
- **实现**：规则优先，LLM 辅助解释
- **约束**：所有评估结果可追溯、可解释

### S4.5 关联分析

- **优先级**：P2
- **描述**：系统应分析健康数据之间的关联关系
- **示例**：症状与体征的关联、症状与药物的关联
- **实现**：LLM 推理辅助

### S4.6 分析结果缓存

- **优先级**：P2
- **描述**：系统应缓存分析结果避免重复计算
- **约束**：数据更新后缓存失效

## S5：通信系统（Communication System）

### S5.1 同步对话

- **优先级**：P0
- **描述**：系统应支持用户发起的实时对话
- **协议**：HTTP/WebSocket（SSE 流式响应）
- **约束**：首字响应延迟 < 2s，支持流式输出

### S5.2 推送通知

- **优先级**：P1
- **描述**：系统应能向用户发送异步推送通知
- **通道**：PWA 浏览器通知（MVP）→ APNs/FCM（远期）
- **类型**：用药提醒、体征记录提醒、异常预警、复诊提醒

### S5.3 定时任务调度

- **优先级**：P1
- **描述**：系统应支持定时任务的创建、修改和删除
- **任务类型**：用药提醒、每日问候、体征记录提醒
- **实现**：APScheduler

### S5.4 消息模板管理

- **优先级**：P1
- **描述**：系统应支持消息模板的定义和管理
- **模板类型**：提醒模板、预警模板、关怀模板、报告模板
- **约束**：模板中的变量需安全注入

### S5.5 推送频率控制

- **优先级**：P1
- **描述**：系统应控制推送频率，单用户每日上限 5 条
- **约束**：支持用户自定义上限和免打扰时段

### S5.6 消息送达确认

- **优先级**：P2
- **描述**：系统应追踪推送消息的送达和阅读状态
- **输出**：送达率、打开率统计

## S6：安全合规系统（Safety & Compliance）

### S6.1 输入安全过滤

- **优先级**：P0
- **描述**：系统应在处理用户输入前进行安全过滤
- **检测**：紧急关键词、恶意输入、注入攻击
- **响应**：疑似紧急输入进入安全状态机；恶意输入按类型拒绝或隔离。规则需记录来源、版本、适用地区和生效日期

### S6.2 输出安全过滤

- **优先级**：P0
- **描述**：系统应在输出给用户前进行安全过滤
- **检测**：诊断性表述、个性化用药建议、超出范围的建议
- **响应**：替换为安全表述或拒绝输出

### S6.3 范围边界控制

- **优先级**：P0
- **描述**：系统应识别超出慢病管理范围的问题
- **超出范围**：急性病诊断、手术建议、替代疗法推荐等
- **响应**：引导用户咨询专业医疗机构

### S6.4 免责声明注入

- **优先级**：P0
- **描述**：系统应在关键位置自动注入免责声明
- **注入点**：首次对话、知识问答、风险评估、就医建议
- **实现**：模板化免责声明，自动追加

### S6.5 数据加密存储

- **优先级**：P1
- **描述**：所有健康数据存储时必须加密（托管/生产化阶段约束；0.0.1 本地原型以数据隔离 + 日志脱敏为基线）
- **算法**：AES-256-GCM
- **密钥管理**：独立密钥存储，不与数据同库

### S6.6 数据加密传输

- **优先级**：P1
- **描述**：所有网络传输必须加密（托管/生产化阶段约束）
- **协议**：HTTPS（TLS 1.3 最低要求）

### S6.7 审计日志

- **优先级**：P0
- **描述**：系统应按最小化原则记录安全和管理事件，不默认复制完整对话或健康数据
- **内容**：时间戳、去标识主体 ID、事件类型、规则/模型/知识版本、安全结果和必要摘要
- **存储**：独立、追加写的审计存储；完整性校验方案另行安全设计
- **保留**：至少 6 个月

### S6.8 用户数据删除

- **优先级**：P0
- **描述**：系统应支持用户请求删除所有个人数据
- **范围**：用户画像、健康数据、对话记录、审计日志中的可关联数据
- **约束**：30 天内完成在线数据删除并提供确认；备份按既定周期过期。依法需保留的审计数据必须去标识化并说明依据

## S7：个性化系统（Personalization）

### S7.1 沟通风格适配

- **优先级**：P2
- **描述**：系统应支持用户选择沟通风格偏好
- **选项**：正式/亲切、详细/简洁
- **实现**：通过 System Prompt 注入风格指令

### S7.2 知识水平适配

- **优先级**：P2
- **描述**：系统应根据用户的知识水平调整医学术语使用程度
- **实现**：基于用户画像中的教育背景 + 对话分析

### S7.3 活跃时段学习

- **优先级**：P2
- **描述**：系统应学习用户的活跃时段并据此优化推送时间
- **实现**：统计用户交互时间分布

### S7.4 健康目标个性化

- **优先级**：P2
- **描述**：系统应基于用户设定的健康目标定制内容
- **示例**：用户关注减重 → 更多体重管理和饮食建议

### S7.5 偏好学习与更新

- **优先级**：P3
- **描述**：系统应从对话中学习用户偏好并持续更新
- **约束**：所有自动学习的偏好需可被用户查看和修正

## S8：会话管理（Session Management）

### S8.1 会话创建与标识

- **优先级**：P0
- **描述**：系统应为每次对话创建唯一会话标识
- **输出**：session_id, user_id, 创建时间
- **约束**：session_id 全局唯一

### S8.2 对话历史管理

- **优先级**：P0
- **描述**：系统应维护当前会话的对话历史
- **存储**：内存滑动窗口（最近 N 轮）
- **约束**：窗口大小可配置，默认 20 轮

### S8.3 会话上下文维护

- **优先级**：P0
- **描述**：系统应维护当前会话的上下文状态
- **内容**：当前话题、活跃的能力模块、临时变量
- **约束**：上下文在会话结束后清除

### S8.4 会话状态机

- **优先级**：P0
- **描述**：系统应维护会话状态机
- **状态**：正常对话 / 健康建档 / 紧急响应 / 体征录入 / 症状录入
- **约束**：状态转换逻辑清晰，异常状态可恢复

### S8.5 会话超时与清理

- **优先级**：P1
- **描述**：系统应在会话超时后自动清理会话资源
- **超时**：默认 30 分钟无交互
- **清理**：释放内存，摘要写入长期记忆

## S9：Agent 核心引擎（Agent Core）

> **这是项目最核心的系统。** Agent 核心引擎不是简单的"意图识别→路由→响应"，而是一个完整的**感知→思考→决策→行动→记忆**循环。所有其他系统（S1-S8、S10）都是为这个循环服务的。

### Agent 决策循环总览

```
用户输入
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  S9.1 感知（Perceive）                              │
│  解析输入、提取意图、识别结构化数据                  │
│  依赖：S3 数据采集                                   │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  S9.2 思考（Think）                                 │
│  检索记忆（S1）、查询知识（S2）、分析上下文           │
│  依赖：S1 记忆系统、S2 知识库                        │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  S9.3 决策（Decide）                                │
│  基于上下文决定下一步行动：追问？记录？分析？警告？    │
│  依赖：S4 分析引擎、S6 安全合规                      │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  S9.4 行动（Act）                                   │
│  执行决策：调用工具、生成回复、存储数据              │
│  依赖：S5 通信系统、S10 基础设施                     │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  S9.5 记忆（Remember）                              │
│  更新短期/长期记忆，保存关键信息                     │
│  依赖：S1 记忆系统                                   │
└─────────────────────────────────────────────────────┘
```

### S9.1 感知：输入解析与意图识别

- **优先级**：P0
- **描述**：Agent 接收用户输入后，进行多层解析
- **解析层次**：
  1. 安全扫描：检查是否包含紧急关键词（胸痛、呼吸困难等）→ 触发 S9.3 紧急决策
  2. 结构化数据提取：正则 + LLM 提取体征数据、时间、数值
  3. 意图分类：理解用户想做什么
- **意图类别**：体征录入、用药确认、症状描述、知识问答、风险评估、情感倾诉、紧急求助、闲聊
- **实现方式**：规则匹配优先 + LLM 分类兜底
- **约束**：安全扫描必须在所有其他处理之前完成；意图分类延迟 < 500ms；准确率 > 90%

### S9.2 思考：上下文构建

- **优先级**：P0
- **描述**：Agent 在理解用户意图后，构建完整的决策上下文
- **上下文要素**：
  1. 用户画像（S1.1）：疾病史、用药方案、过敏史、目标范围
  2. 近期健康数据（S1.2）：最近 7-30 天的体征记录、趋势
  3. 对话历史（S1.3）：当前会话的上下文
  4. 相关知识（S2.4）：与当前意图匹配的医学知识
- **实现方式**：
  - 记忆检索（S1.6）获取用户画像和近期数据
  - 知识检索（S2.4）获取相关医学知识
  - 组装为结构化的决策上下文，传递给 LLM
- **约束**：上下文构建延迟 < 500ms；检索结果不超过 LLM 上下文窗口的 60%（留空间给决策和回复）

### S9.3 决策：多步推理与行动规划

- **优先级**：P0
- **描述**：Agent 基于上下文进行推理，决定下一步行动。**这是 Agent 区别于传统 Chatbot 的核心。**
- **决策类型**：
  | 类型 | 触发条件 | 决策内容 |
  |------|----------|----------|
  | 紧急响应 | 安全扫描命中紧急关键词 | 立即触发安全状态机，引导就医 |
  | 数据记录 | 识别到有效的健康数据 | 校验 → 存储 → 分析 → 回复 |
  | 异常追问 | 数据异常或风险升高 | 记录数据 + 主动追问（服药？症状？） |
  | 信息追问 | 信息不完整 | 追问缺失字段 |
  | 知识问答 | 询问医学知识 | 检索知识 → 生成回复 |
  | 趋势分析 | 询问健康趋势 | 查询数据 → 计算 → 总结 |
  | 情感支持 | 识别到负面情绪 | 共情回应 + 温和引导 |
  | 澄清确认 | 意图不明确 | 追问澄清 |
- **决策原则**：
  - 安全优先：任何疑似紧急情况必须先于其他处理
  - 宁可多问一句：不确定时追问，不做假设
  - 确定性优先：能用规则判断的不用 LLM
- **实现方式**：
  - 紧急判断：安全状态机（S6），确定性规则
  - 数据校验：确定性规则（S3.3）
  - 异常判断：规则引擎 + 阈值（S4.2）
  - 复杂决策：LLM 推理（提供完整的上下文 + 决策指引）
- **约束**：紧急判断延迟 < 100ms；LLM 决策延迟 < 2s

### S9.4 行动：工具调用与响应生成

- **优先级**：P0
- **描述**：Agent 执行决策，调用工具，生成最终回复
- **工具调用（P1）**：
  - 数据查询工具：查询体征历史、趋势数据
  - 数据写入工具：记录体征、用药确认
  - 知识检索工具：查询医学知识库
  - 计算工具：达标率、平均值、变化率
- **实现方式**：LangChain/LangGraph Function Calling
- **响应生成**：
  - 安全场景（紧急、免责、降级）：使用预设模板，不经过 LLM
  - 通用场景：LLM 生成，基于上下文 + 决策结果
  - 流式输出（S9.6）：SSE 逐 token 返回
- **约束**：安全场景必须使用模板，不能依赖 LLM 生成

### S9.5 记忆：状态更新

- **优先级**：P0
- **描述**：每轮对话结束后，Agent 更新相关记忆
- **更新内容**：
  1. 新增的健康数据写入健康时间线（S1.2）
  2. 画像变更写入用户画像（S1.1）
  3. 对话历史追加到会话记忆（S1.3）
  4. 关键事件生成摘要写入长期记忆（S1.5，P2）
- **约束**：记忆更新不阻塞用户回复（异步进行）；画像更新必须经用户确认

### S9.6 多轮对话管理

- **优先级**：P0
- **描述**：Agent 维护多轮对话的上下文连贯性
- **功能**：
  - 维护对话状态（当前话题、待确认项、追问链）
  - 支持话题切换和回退
  - 支持用户在对话中修正信息（"不对，是 135 不是 153"）
- **实现**：对话状态机 + 上下文窗口管理

### S9.7 流式响应

- **优先级**：P0
- **描述**：Agent 支持流式输出（SSE），逐 token 返回响应
- **约束**：首字延迟 < 2s；输出速率 ≥ 20 tokens/s

### S9.8 主动行为

- **优先级**：P1
- **描述**：Agent 不仅在用户发消息时响应，还能主动发起交互
- **主动行为类型**：
  - 检测到异常值后，在合理时间内主动追问
  - 长期未记录数据时，主动提醒
  - 阶段性健康总结（周报、月报）
- **实现**：定时任务（S5）+ 事件驱动
- **约束**：主动行为频率可控，避免过度打扰

### S9.9 错误处理与降级

- **优先级**：P0
- **描述**：Agent 在各环节失败时优雅降级
- **降级策略**：
  | 故障环节 | 降级行为 |
  |----------|----------|
  | LLM 不可用 | 返回预设安全回复 + 提示稍后再试 |
  | 记忆检索失败 | 仅使用当前对话上下文，不做历史关联 |
  | 知识检索失败 | 回复中说明"暂时无法查询相关知识" |
  | 数据库不可用 | 返回友好错误提示，不暴露技术细节 |
  | 紧急判断失败 | 默认按紧急情况处理（保守策略） |
- **约束**：任何情况下不能返回空白、错误堆栈或技术细节

### S9.10 安全边界

- **优先级**：P0
- **描述**：Agent 核心引擎内嵌安全约束
- **规则**：
  - 所有 LLM 生成的回复必须经过 S6 安全过滤器
  - 不做诊断性表述（"您可能患有XX"→ 禁止）
  - 不提供个性化用药建议（"您应该吃XX药"→ 禁止）
  - 所有医学建议附带免责声明

## S10：基础设施（Infrastructure）

### S10.1 配置管理

- **优先级**：P0
- **描述**：系统应支持集中化的配置管理
- **内容**：环境变量、模型参数、功能开关、阈值配置
- **实现**：pydantic-settings
- **约束**：敏感配置（API Key）不得硬编码

### S10.2 日志系统

- **优先级**：P0
- **描述**：系统应提供结构化日志
- **级别**：DEBUG / INFO / WARNING / ERROR / CRITICAL
- **格式**：JSON 结构化日志
- **约束**：日志中不得包含用户健康数据明文

### S10.3 数据库管理

- **优先级**：P0
- **描述**：系统应提供数据库连接管理和迁移机制
- **实现**：SQLAlchemy + Alembic（迁移）
- **MVP 数据库**：SQLite（文件存储）
- **约束**：支持未来迁移到 PostgreSQL

### S10.4 LLM 网关

- **优先级**：P0
- **描述**：系统应提供统一的 LLM 调用接口
- **功能**：模型选择、参数配置、重试机制、超时控制、速率限制
- **约束**：支持多模型切换（DeepSeek / OpenAI 兼容）

### S10.5 异步框架

- **优先级**：P0
- **描述**：系统应基于异步框架构建，支持并发请求
- **实现**：asyncio + FastAPI
- **约束**：单进程支持 50+ 并发连接

### S10.6 健康检查

- **优先级**：P1
- **描述**：系统应提供健康检查端点
- **端点**：GET /health
- **检查项**：数据库连接、LLM 服务可用性、内存使用

### S10.7 API 文档

- **优先级**：P0
- **描述**：系统应自动生成 API 文档
- **实现**：FastAPI 自动生成 OpenAPI（Swagger UI）
- **约束**：文档与代码同步更新

### S10.8 容器化支持

- **优先级**：P1
- **描述**：系统应提供 Dockerfile 和 Docker Compose 配置
- **约束**：支持一键启动开发环境
