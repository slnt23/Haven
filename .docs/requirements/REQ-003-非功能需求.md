## 一、性能需求

### NF1.1 对话响应延迟

- **优先级**：P0
- **指标**：首字响应时间（TTFB）< 2 秒
- **测量**：从用户发送消息到第一个 token 返回的时间
- **约束**：P95 延迟 < 3 秒

### NF1.2 流式输出速率

- **优先级**：P0
- **指标**：流式输出速率 ≥ 20 tokens/秒
- **约束**：用户感知的"打字"效果流畅

### NF1.3 并发用户数

- **优先级**：P0
- **指标**：MVP 阶段支持 50+ 并发连接
- **约束**：单进程部署，不引入分布式

### NF1.4 数据查询延迟

- **优先级**：P1
- **指标**：健康数据查询 < 200ms，知识检索 < 500ms
- **约束**：P95 延迟 < 2x 目标值

### NF1.5 内存占用

- **优先级**：P1
- **指标**：单用户会话内存 < 50MB，系统总内存 < 2GB
- **约束**：支持 4GB RAM 的轻量服务器部署

### NF1.6 存储空间

- **优先级**：P1
- **指标**：单用户年数据量 < 50MB（含日志）
- **约束**：SQLite 单文件 < 10GB 时性能不显著下降

## 二、可用性需求

### NF2.1 系统可用率

- **优先级**：P1
- **指标**：MVP 阶段 > 99%（允许计划内维护停机）
- **约束**：生产环境 > 99.5%

### NF2.2 故障恢复

- **优先级**：P0
- **描述**：系统崩溃后应能自动恢复，数据不丢失
- **实现**：SQLite WAL 模式 + 自动重启
- **约束**：恢复时间 < 5 分钟

### NF2.3 LLM 服务降级

- **优先级**：P0
- **描述**：LLM 服务不可用时应返回预设的安全回复
- **输出**："抱歉，我暂时无法处理您的请求，请稍后再试。如有紧急情况，请拨打 120。"
- **约束**：绝不能返回空白或错误堆栈

### NF2.4 数据库容错

- **优先级**：P0
- **描述**：数据库操作失败时应重试并记录错误
- **重试**：最多 3 次，指数退避
- **降级**：返回友好错误提示

### NF2.5 定时任务可靠性

- **优先级**：P1
- **描述**：用药提醒等关键定时任务应有重试机制
- **约束**：提醒通知的丢失率 < 1%

## 三、安全性需求

### NF3.1 数据传输加密

- **优先级**：P0
- **描述**：所有客户端-服务器通信必须加密
- **协议**：HTTPS（TLS 1.3）
- **约束**：禁止 HTTP 明文传输

### NF3.2 数据存储加密

- **优先级**：P0
- **描述**：所有健康数据在存储时必须加密
- **算法**：AES-256-GCM
- **密钥管理**：密钥与数据分离存储

### NF3.3 用户认证

- **优先级**：P0
- **描述**：系统应支持用户身份认证
- **MVP 方案**：JWT Token + 密码哈希（bcrypt）
- **约束**：密码不得明文存储，Token 有过期时间

### NF3.4 访问控制

- **优先级**：P0
- **描述**：用户只能访问自己的数据
- **实现**：基于 user_id 的数据隔离
- **约束**：任何 API 调用必须验证用户身份

### NF3.5 输入注入防护

- **优先级**：P0
- **描述**：系统应防护常见的注入攻击
- **类型**：SQL 注入、Prompt 注入、XSS
- **实现**：参数化查询 + 输入过滤 + 输出编码

### NF3.6 API 速率限制

- **优先级**：P1
- **描述**：系统应限制 API 调用频率
- **限制**：单用户 60 次/分钟，单 IP 120 次/分钟
- **响应**：429 Too Many Requests

### NF3.7 敏感信息脱敏

- **优先级**：P0
- **描述**：日志中不得包含用户健康数据明文
- **实现**：日志输出前自动脱敏姓名、身份证号等
- **约束**：健康数据仅在审计日志中加密存储

### NF3.8 会话安全

- **优先级**：P0
- **描述**：会话 Token 应安全生成和管理
- **实现**：随机 Token + 过期时间 + 刷新机制
- **约束**：Token 不得出现在 URL 中

## 四、合规性需求

### NF4.1 个人信息保护

- **优先级**：P0
- **描述**：系统需符合《个人信息保护法》要求
- **要求**：数据最小化、目的限制、用户知情同意、删除权
- **约束**：首次使用时必须展示隐私政策并获取用户同意

### NF4.2 医疗免责声明

- **优先级**：P0
- **描述**：系统必须在关键触点上展示医疗免责声明
- **位置**：首次使用、知识问答、风险评估、就医建议
- **内容**：明确"不是医疗设备，不提供诊断，仅供参考"

### NF4.3 数据保留策略

- **优先级**：P0
- **描述**：系统应定义明确的数据保留策略
- **健康数据**：用户活跃期间永久保留，删除请求后 30 天内清除
- **审计日志**：至少保留 6 个月
- **对话记录**：默认保留 12 个月，用户可提前删除

### NF4.4 数据可移植性

- **优先级**：P1
- **描述**：用户应能导出其所有健康数据
- **格式**：CSV（结构化数据）+ JSON（完整数据）
- **约束**：导出请求 7 天内完成

### NF4.5 未成年人保护

- **优先级**：P1
- **描述**：系统应限制未成年人使用
- **约束**：注册时需确认年满 18 岁，或由监护人代管

## 五、可维护性需求

### NF5.1 代码质量

- **优先级**：P0
- **描述**：代码须通过静态类型检查和 linting
- **工具**：mypy（strict mode）+ ruff
- **约束**：CI 中强制检查，不通过不允许合并

### NF5.2 测试覆盖率

- **优先级**：P0
- **描述**：核心业务逻辑须有单元测试覆盖
- **指标**：核心模块覆盖率 > 80%
- **约束**：关键路径（安全、数据校验）100% 覆盖

### NF5.3 API 文档

- **优先级**：P0
- **描述**：API 接口须有完整的文档
- **实现**：FastAPI 自动生成 OpenAPI + 手动补充描述
- **约束**：文档与代码保持同步

### NF5.4 代码规范

- **优先级**：P0
- **描述**：代码应遵循统一的编码规范
- **实现**：ruff 自动格式化 + 项目级 .editorconfig
- **约束**：CI 中强制检查格式

### NF5.5 部署文档

- **优先级**：P1
- **描述**：系统应提供清晰的部署文档
- **内容**：环境要求、安装步骤、配置说明、启动命令
- **约束**：新开发者 30 分钟内能完成本地部署

## 六、可扩展性需求

### NF6.1 数据库可替换

- **优先级**：P0
- **描述**：数据库层应抽象，支持从 SQLite 迁移到 PostgreSQL
- **实现**：SQLAlchemy ORM 抽象层
- **约束**：迁移时仅需修改连接字符串

### NF6.2 模型可替换

- **优先级**：P0
- **描述**：LLM 模型应可替换，不绑定特定厂商
- **实现**：LLM Gateway 抽象层 + 配置驱动
- **约束**：更换模型仅需修改配置，无需改代码

### NF6.3 能力模块可插拔

- **优先级**：P1
- **描述**：Agent 能力模块应支持独立开发和插拔
- **实现**：能力模块注册机制 + 统一接口
- **约束**：新增能力模块不影响现有模块

### NF6.4 水平扩展支持

- **优先级**：P2
- **描述**：架构应预留水平扩展的可能性
- **考虑**：无状态 API 层 + 独立数据库 + 独立 LLM 服务
- **约束**：MVP 阶段不实现，但架构不阻止

## 七、用户体验需求

### NF7.1 界面简洁

- **优先级**：P0
- **描述**：用户界面应简洁直观，适合 40-70 岁用户
- **要求**：大字体、高对比度、清晰的按钮、最少的学习成本
- **约束**：首次使用 5 分钟内完成健康建档

### NF7.2 多端适配

- **优先级**：P1
- **描述**：界面应适配手机和桌面端
- **实现**：响应式 Web 设计
- **约束**：手机端为主要使用场景

### NF7.3 离线提示

- **优先级**：P2
- **描述**：网络断开时应给出友好提示
- **输出**："网络连接已断开，请检查网络后重试"

### NF7.4 加载状态

- **优先级**：P0
- **描述**：所有异步操作应有加载状态指示
- **要求**：消息发送后显示"正在输入..."动画

### NF7.5 错误提示

- **优先级**：P0
- **描述**：错误提示应使用用户友好的语言
- **要求**：不使用技术术语（如"500 Internal Server Error"）
- **示例**："出了点问题，请稍后重试"

### NF7.6 无障碍访问

- **优先级**：P2
- **描述**：界面应支持基本的无障碍访问
- **要求**：支持屏幕阅读器、键盘导航、足够的颜色对比度
