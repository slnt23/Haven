## Agent 闭环基线（横切硬性要求，先于交付项存在）

0.0.1 的每条交付项都必须以 **Agent 决策循环（感知→思考→决策→行动→记忆）** 的形态交付（见 [README 主路线](README.md)）。下列最小机件是横切硬性要求，为所有交付项服务：

| # | 机件 | 硬性要求 | 参考 |
| - | ---- | -------- | ---- |
| B1 | 会话级状态机 | 按用户/会话隔离；**禁止模块级全局单例共享状态** | REQ-002 S8.4 |
| B2 | 记忆注入上下文 | "思考"前读取该用户画像与近期体征注入决策上下文 | REQ-002 S9.2 / S1.6 |
| B3 | 多轮确认闭环 | 异常二次确认、建档引导为"可续接"的对话状态流（用户回"确认"能接上） | REQ-002 S9.6 |
| B4 | 安全状态按用户隔离 | 紧急/降级只作用于当前用户；判定走版本化安全规则 | REQ-002 S6.1 / S9.9 |
| B5 | LLM 降级矩阵 | LLM 不可用时录入/校验/趋势不中断；DB 不可用不得谎报成功 | REQ-002 S9.9 / REQ-003 NF2.3/NF2.4 |
| B6 | 流式输出 | 回复走 SSE 逐 token 输出 | REQ-002 S5.1 / S9.7 |

> **合入门槛**：某交付项仅通过"REST 端点冒烟测试"不算验收，必须证明其对话路径跑在 B1-B6 之上，并通过 [README 2.3 偏离信号自查](README.md)。

## 发布检查

- 每行必须对应至少一个**真实可运行的自动化测试**（不是"计划路径"）。
- 测试必须覆盖正常、非法输入、依赖故障和安全边界。
- 闭环基线 B1-B6 各有针对性测试：会话状态机、记忆注入、多轮确认、按用户隔离、降级、流式。
- 不允许使用真实患者数据作为测试夹具。
- 安全规则测试分别报告误报和漏报，不以"100% 可靠"作为验收表述。
- 任何新增 P0 必须先更新对应 REQ 文档，再更新本表。
