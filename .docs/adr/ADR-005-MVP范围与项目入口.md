# ADR-005：MVP 范围与项目入口

> 状态：已接受
> 日期：2026-09-01
> 依赖：ADR-001

## 背景

原需求将多个独立产品级能力同时列为 MVP，无法用一条用户路径快速验证产品价值。仓库目前也没有已实现的产品入口。

## 决策

版本 `0.0.1` 只交付以下垂直闭环：

```text
知情同意与高血压建档
→ 手工录入血压
→ 单位、范围和逻辑校验
→ 异常值二次确认
→ 七日趋势展示
→ 疑似紧急情况的保守就医提示
```

### 产品入口

1. 首个入口为 `haven web`，启动患者端 Web/API。
2. 第二个入口为 `haven check`，只读检查配置、数据库和安全规则是否可用。
3. 入口实现前不在 `pyproject.toml` 声明命令，避免发布无效入口。
4. 旧 CLI REPL、飞书、Daemon 和通用任务入口不再继承；新入口必须通过独立 ADR 评审。

### 不在 0.0.1 内

- 自然语言健康数据抽取
- 用药提醒、漏服建议和药物相互作用
- 通用医学知识问答
- 家庭协同和多患者管理
- 蓝牙设备、推送、报告和多智能体编排

## 验收门槛

- 上述闭环的正常、非法输入、服务降级和安全路径均有自动化测试。
- 所有 P0 需求可追踪到验收标准和测试。
- 安全规则记录来源、版本、适用地区和生效日期。
- 未通过医学与隐私评审前，仅允许使用合成数据进行开发验证。

## 后果

此决策会下调 ADR-002 和 REQ-001/002/003 中超出闭环的原 P0 项。它们仍保留在产品路线图中，但不阻塞 `0.0.1` 交付。
