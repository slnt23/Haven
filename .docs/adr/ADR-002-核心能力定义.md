# ADR-002：核心能力定义 — 从 Agent 视角出发

> 状态：提议中
> 日期：2026-08-25
> 依赖：ADR-001

---

## 一、背景

在确定了"个人慢病管理智能体"的定位后，需要明确这个 Agent 应该具备哪些面向用户的核心能力。这里采用 **Agent-First** 的思考方式：先想象一个理想的慢病管理 Agent 会做什么，再反推需要什么底层支撑。

### 2.2 十二大核心能力详细定义

#### C1：健康画像管理（Health Profile）

**用户故事**：作为慢病患者，我希望 Agent 能记住我的病史、过敏史、用药方案等基本信息，而不是每次对话都要我重新说一遍。

**功能要点**：

- 基础信息采集：年龄、性别、身高、体重
- 疾病史：确诊疾病、确诊时间、严重程度
- 用药方案：药品名称、剂量、频次、起止时间
- 过敏史：药物过敏、食物过敏
- 家族史：直系亲属的重大疾病史
- 生活习惯：吸烟、饮酒、运动频率、饮食偏好
- 健康画像的持续更新和修正

**交互方式**：首次引导式问卷 + 对话中自然补充

#### C2：体征追踪与分析（Vitals Tracking）

**用户故事**：作为高血压患者，我希望每天记录血压值，Agent 能帮我分析趋势，告诉我控制得好不好。

**功能要点**：

- 关键体征录入：血压（收缩压/舒张压）、血糖（空腹/餐后）、心率、体重、体温、血氧
- 支持手动输入和蓝牙设备同步（远期）
- 趋势图表展示（周/月/季度）
- 异常值自动标记和提醒
- 与目标范围的对比分析
- 达标率统计

**交互方式**：结构化输入（表单/快捷按钮）+ 自然语言（"今天血压 135/85"）

#### C3：用药管理（Medication Management）

**用户故事**：作为糖尿病患者，我经常忘记吃药，想知道什么时候该吃、吃了没有、漏了怎么办。

**功能要点**：

- 用药方案管理：药品、剂量、频次、时间窗口
- 用药提醒：到时间推送通知
- 服药确认：记录是否已服用
- 漏服处理：根据药品类型给出漏服建议（补服/跳过）
- 依从性统计：周/月服药率
- 药物相互作用检查（基础版）
- 处方续方提醒：药快吃完时提醒

**交互方式**：主动推送 + 被动查询

#### C4：症状记录与追踪（Symptom Tracking）

**用户故事**：作为慢病患者，我有时会有些不舒服，希望记录下来，Agent 能帮我判断是否需要注意。

**功能要点**：

- 症状录入：类型、严重程度（1-5级）、持续时间、触发因素
- 症状时间线：按时间排列的症状记录
- 症状与体征的关联分析
- 症状趋势识别："最近一周头痛频率增加了"
- 与药物的关联："是否和换药有关？"

**交互方式**：自然语言描述 + 结构化补充

#### C5：风险评估与预警（Risk Assessment）

**用户故事**：作为高血压患者，我希望 Agent 能告诉我当前的血压控制情况是否有风险，什么时候应该去看医生。

**功能要点**：

- 基于指南的风险分层（如血压分级：正常/正常高值/1级/2级/3级）
- 多指标联合风险评估
- 风险趋势变化追踪
- 预警阈值设置和通知
- 就医建议：明确告知"建议近期就诊"或"立即就医"

**安全边界**：

- 风险评估基于公开的临床指南，不做个性化诊断
- 所有预警附带"请咨询医生"的免责声明
- 紧急情况（如极高危）直接建议拨打急救电话

#### C6：生活方式干预（Lifestyle Intervention）

**用户故事**：作为糖尿病患者，我希望 Agent 能根据我的情况，给我饮食和运动方面的建议。

**功能要点**：

- 饮食建议：基于疾病类型和指标的健康饮食指导
- 运动建议：适合的运动类型、强度、时长
- 睡眠管理：睡眠时长和质量追踪
- 压力管理：简单的放松技巧和正念引导
- 行为目标设定：SMART 目标（如"本周每天步行 30 分钟"）
- 目标达成追踪和鼓励

**交互方式**：主动建议 + 用户询问

#### C7：医学知识问答（Knowledge Q&A）

**用户故事**：作为慢病患者，我有很多关于疾病的问题，希望 Agent 能用通俗易懂的方式回答我。

**功能要点**：

- 疾病基础知识：病因、症状、并发症
- 检查指标解读：化验单结果的含义
- 药物知识：作用机制、副作用、注意事项
- 生活方式知识：饮食、运动、心理调节
- 回答限定在医学知识范围，不做诊断
- 回答附带信息来源，增强可信度
- 对不确定的问题坦诚说"不知道，建议咨询医生"

**安全边界**：

- 知识来源限定在权威医学指南和教科书
- 不回答"我应该吃什么药"之类的个性化用药建议
- 所有回答末尾附带"以上信息仅供参考，请咨询医生"

#### C8：情感支持与陪伴（Emotional Support）

**用户故事**：作为慢病患者，有时候会感到焦虑和沮丧，希望有人能听我说说话，给我一些鼓励。

**功能要点**：

- 情绪状态识别：通过对话内容感知用户的情绪状态
- 共情回应：理解用户的感受，给予情感支持
- 正向鼓励：对健康行为的改善给予肯定
- 焦虑和抑郁筛查：使用标准化量表（PHQ-9/GAD-7）
- 严重心理问题转介：识别自杀风险，提供心理援助热线

**安全边界**：

- 不是心理治疗，不提供心理咨询
- 识别到严重心理问题时，引导寻求专业帮助

#### C9：复诊与随访管理（Follow-up Management）

**用户故事**：作为慢病患者，我希望 Agent 能提醒我什么时候该去复查，需要提前做哪些准备。

**功能要点**：

- 复诊计划管理：记录医生的复诊建议
- 复诊提醒：提前 3-7 天提醒
- 检查准备提醒：如"明天抽血，今晚 8 点后禁食"
- 复诊结果记录：记录医生的建议和调整
- 随访周期建议：基于指南推荐的标准随访频率

#### C10：主动关怀（Proactive Check-in）

**用户故事**：作为慢病患者，我希望 Agent 能主动关心我，而不是等我打开 App 才理我。

**功能要点**：

- 每日问候：根据用户习惯的时间推送
- 体征记录提醒：到时间提醒测量和记录
- 异常值跟进：检测到异常后主动询问情况
- 阶段性总结：每周/每月健康报告
- 季节性提醒：如"天气转凉，注意血压波动"
- 合理频率控制：避免过度打扰

**交互方式**：推送通知为主，用户可自定义频率和时段

#### C11：安全兜底（Safety Net）

**用户故事**：作为患者和开发者，我需要确保 Agent 不会给出危险的错误建议。

**功能要点**：

- 紧急情况识别：胸痛、严重呼吸困难、意识模糊等关键词触发
- 紧急响应：立即建议拨打 120 或前往急诊
- 免责声明：每次对话中关键位置嵌入免责信息
- 超出范围识别：识别到超出慢病管理范围的问题时引导专业渠道
- 审计日志：所有交互记录完整可追溯

#### C12：家庭协同（Family Collaboration）

**用户故事**：作为患者家属，我希望了解家人的健康管理情况，在需要时提供帮助。

**功能要点**（远期规划）：

- 家属账号绑定
- 家属查看患者健康摘要（经患者授权）
- 家属接收异常预警
- 家属代为记录（如帮助老人记录体征）

## 三、能力优先级

> `0.0.1` 范围已由 ADR-005 收敛。下列 Phase 划分保留为产品路线图，其中原 MVP 标记不再代表 `0.0.1` 发布门槛。

### 3.1 MVP（最小可行产品）— Phase 1

| 优先级 | 能力         | 理由                             |
| ------ | ------------ | -------------------------------- |
| P0     | C1 健康画像  | 所有能力的基础，必须先有用户画像 |
| P0     | C2 体征追踪  | 慢病管理的核心数据来源           |
| P0     | C3 用药管理  | 依从性是慢病管理的第一痛点       |
| P0     | C7 知识问答  | 用户最自然的使用方式             |
| P0     | C11 安全兜底 | 医疗场景的生命线                 |

### 3.2 Phase 2

| 优先级 | 能力         | 理由                          |
| ------ | ------------ | ----------------------------- |
| P1     | C4 症状记录  | 补充体征之外的主观数据        |
| P1     | C5 风险评估  | 基于 Phase 1 数据提供风险洞察 |
| P1     | C8 情感陪伴  | 提升用户粘性和满意度          |
| P1     | C10 主动关怀 | 从被动到主动的关键转变        |

### 3.3 Phase 3

| 优先级 | 能力            | 理由                     |
| ------ | --------------- | ------------------------ |
| P2     | C6 生活方式干预 | 需要更丰富的数据和知识库 |
| P2     | C9 复诊管理     | 相对独立的功能模块       |
| P2     | C12 家庭协同    | 涉及多用户和权限管理     |

## 四、后果

### 4.1 正面后果

- 12 个能力模块清晰定义了 Agent 的完整功能范围
- 优先级划分使得可以分阶段交付
- 每个能力都有明确的用户故事，便于验证

### 4.2 风险

- 12 个能力可能过多，MVP 需要严格控制范围
- 部分能力（如风险评估、生活方式干预）需要大量的医学知识支撑
- 情感陪伴和安全兜底的能力边界需要持续打磨
