# ADR-003：基础能力架构 — 反推所需支撑系统

> 状态：提议中
> 日期：2026-08-25
> 依赖：ADR-001, ADR-002

---

## 一、背景

在 ADR-002 中定义了 Agent 的 12 大核心能力。现在需要反推：**要支撑这些能力，底层需要哪些基础系统？**

这个反推过程是 Agent-First 方法论的核心：不做"万能框架"，只做"够用且可扩展的基座"。

---

### 2.2 十大基础系统详细定义

#### S1：记忆系统（Memory System）

**支撑的 Agent 能力**：C1 健康画像、C2 体征追踪、C3 用药管理、C4 症状记录、C8 情感陪伴

**职责**：所有需要"记住"的信息都经过此系统

**存储层次**：

| 层级           | 内容                                             | 存储方式                          | 生命周期      |
| -------------- | ------------------------------------------------ | --------------------------------- | ------------- |
| **用户画像**   | 疾病史、过敏史、用药方案、生活习惯等结构化信息   | 关系型数据库（SQLite/PostgreSQL） | 永久          |
| **健康时间线** | 体征记录、用药记录、症状记录、复诊记录等时序数据 | 时序存储 + 关系型数据库           | 永久          |
| **对话记忆**   | 近期对话历史，用于当前会话上下文                 | 内存缓存 + 近期摘要               | 会话级 + 短期 |
| **长期记忆**   | 关键健康事件、用户偏好、重要对话摘要             | 向量数据库 + 结构化存储           | 长期          |

**设计原则**：

- 健康数据必须结构化存储，不能只靠向量检索
- 对话记忆有窗口限制，超出的部分做摘要压缩
- 长期记忆需要遗忘机制，不是无限存储

**MVP 方案**：

- 用户画像：SQLite 表
- 健康时间线：SQLite 时序表
- 对话记忆：内存滑动窗口（最近 N 轮对话）
- 长期记忆：关键事件摘要（暂不引入向量数据库）

#### S2：知识库（Knowledge Base）

**支撑的 Agent 能力**：C5 风险评估、C6 生活方式干预、C7 知识问答

**职责**：提供结构化、可信的医学知识

**知识来源**：

| 类型     | 内容                                                        | 来源             | 更新频率 |
| -------- | ----------------------------------------------------------- | ---------------- | -------- |
| 疾病知识 | 高血压、糖尿病、COPD 等慢病的病因、症状、诊断标准、治疗原则 | 临床指南、教科书 | 半年     |
| 药物知识 | 常用慢病药物的作用机制、用法用量、副作用、禁忌              | 药品说明书、药典 | 季度     |
| 检查知识 | 常见检查指标的正常范围、异常含义                            | 医学检验学       | 半年     |
| 生活方式 | 饮食建议、运动指导、心理调节                                | 康复医学、营养学 | 季度     |
| 风险评估 | 各疾病的风险分层标准和算法                                  | 临床指南         | 半年     |

**存储方式**：

- 结构化知识图谱（JSON/YAML 文件 or 轻量级图数据库）
- 非结构化文本（Markdown 文件，用于 RAG 检索）
- 关键词索引（快速匹配）

**MVP 方案**：

- 知识以 Markdown + YAML Frontmatter 形式存储
- 启动时加载到内存
- 关键词匹配 + 简单语义检索（嵌入向量）
- 不引入重型知识图谱

#### S3：数据采集系统（Data Collection）

**支撑的 Agent 能力**：C2 体征追踪、C3 用药管理、C4 症状记录

**职责**：从用户那里获取结构化和非结构化的健康数据

**采集方式**：

| 方式         | 适用场景               | 优先级 |
| ------------ | ---------------------- | ------ |
| 自然语言输入 | "今天血压 135/85"      | P0     |
| 结构化表单   | 初次建档、每日体征录入 | P0     |
| 快捷按钮     | 服药确认、症状选择     | P1     |
| 蓝牙设备同步 | 血压计、血糖仪         | P2     |
| 图片识别     | 化验单拍照识别         | P2     |

**数据验证**：

- 数值范围校验（如收缩压 60-300 mmHg）
- 逻辑一致性校验（如收缩压 > 舒张压）
- 异常值标记和二次确认

**MVP 方案**：

- 自然语言解析（LLM 提取结构化数据）
- 简易表单（预设选项 + 滑动选择）
- 基础数值校验

#### S4：分析引擎（Analysis Engine）

**支撑的 Agent 能力**：C5 风险评估、C2 体征追踪（趋势分析）、C4 症状记录（关联分析）

**职责**：对健康数据进行分析，产生洞察

**分析类型**：

| 类型       | 输入               | 输出                       | 实现方式   |
| ---------- | ------------------ | -------------------------- | ---------- |
| 趋势分析   | 时间序列体征数据   | 趋势图、变化方向、变化速度 | 统计计算   |
| 异常检测   | 单次体征值         | 是否异常、异常等级         | 规则引擎   |
| 达标率统计 | 时间段内体征数据   | 达标百分比、不达标天数     | 统计计算   |
| 风险评估   | 多维度健康数据     | 风险等级、风险因素列表     | 规则 + LLM |
| 关联分析   | 症状 + 体征 + 用药 | 可能的关联关系             | LLM 推理   |

**设计原则**：

- 确定性计算（统计、规则）不依赖 LLM
- LLM 仅用于需要推理和解释的场景
- 分析结果可追溯、可解释

**MVP 方案**：

- 趋势分析：移动平均、达标率、变化率
- 异常检测：基于指南的阈值规则
- 风险评估：基于指南的分层规则
- 关联分析：LLM 辅助（低优先级）

#### S5：通信系统（Communication System）

**支撑的 Agent 能力**：C10 主动关怀、C3 用药提醒、C9 复诊提醒

**职责**：管理 Agent 与用户之间的消息传递

**通信模式**：

| 模式       | 说明                                     | 优先级 |
| ---------- | ---------------------------------------- | ------ |
| 同步对话   | 用户发起，Agent 实时响应                 | P0     |
| 异步推送   | Agent 主动发送通知（用药提醒、异常预警） | P1     |
| 定时任务   | 每日问候、每日体征记录提醒               | P1     |
| 阶段性报告 | 周报、月报                               | P2     |

**消息类型**：

- 对话消息（一问一答）
- 提醒消息（用药、测量、复诊）
- 预警消息（异常指标、风险提示）
- 报告消息（周报、月报）
- 关怀消息（问候、鼓励）

**MVP 方案**：

- 同步对话：Web UI（单页应用）
- 推送：浏览器通知（PWA）
- 定时任务：后端调度器

#### S6：安全合规系统（Safety & Compliance）

**支撑的 Agent 能力**：C11 安全兜底（贯穿所有能力）

**职责**：确保 Agent 的安全性和合规性

**安全层次**：

| 层次     | 内容                                   | 实现方式              |
| -------- | -------------------------------------- | --------------------- |
| 输入安全 | 识别紧急情况关键词（胸痛、呼吸困难等） | 关键词 + LLM 分类     |
| 输出安全 | 确保每条回复不包含诊断性表述           | 输出过滤器 + LLM 自查 |
| 范围安全 | 识别超出慢病管理范围的问题             | 意图分类器            |
| 数据安全 | 健康数据加密存储和传输                 | AES 加密 + HTTPS      |
| 隐私合规 | 符合《个人信息保护法》要求             | 数据最小化 + 用户授权 |
| 审计追溯 | 完整记录所有交互                       | 审计日志              |

**紧急响应流程**：

1. 识别紧急关键词
2. 立即回复"请立即拨打 120 或前往最近医院急诊科"
3. 不进行任何其他对话
4. 记录紧急事件

**MVP 方案**：

- 紧急关键词列表（硬编码 + 定期更新）
- 输出模板化（确保安全表述）
- 基础加密（AES）
- 审计日志（SQLite）

#### S7：个性化系统（Personalization）

**支撑的 Agent 能力**：C8 情感陪伴、C6 生活方式干预、C10 主动关怀

**职责**：让 Agent 的交互更贴合个体用户

**个性化维度**：

| 维度     | 内容                           | 实现方式                |
| -------- | ------------------------------ | ----------------------- |
| 健康状态 | 基于用户具体疾病和指标定制内容 | 规则匹配                |
| 沟通风格 | 正式/亲切、详细/简洁           | 用户偏好设置 + 行为学习 |
| 知识水平 | 医学术语使用程度               | 用户画像 + 对话分析     |
| 使用习惯 | 活跃时段、交互频率偏好         | 行为统计                |
| 目标偏好 | 用户关注的健康目标             | 用户设定                |

**MVP 方案**：

- 基于健康画像的规则匹配（主要）
- 用户偏好设置（手动）
- 暂不做行为学习（Phase 2）

#### S8：会话管理系统（Session Management）

**支撑的 Agent 能力**：所有对话能力

**职责**：管理单次对话的生命周期和上下文

**会话要素**：

- 会话 ID 和用户 ID
- 对话历史（最近 N 轮）
- 当前上下文（用户正在讨论的话题）
- 对话状态（正常/紧急/建档中等）
- 临时变量（如正在录入的体征数据）

**MVP 方案**：

- 内存会话管理（单进程）
- 对话历史滑动窗口（最近 20 轮）
- 状态机：正常 ↔ 建档 ↔ 紧急

#### S9：Agent 核心引擎（Agent Core）

**支撑的 Agent 能力**：所有能力

**职责**：Agent 的"大脑"，负责意图理解、任务规划和执行

**核心组件**：

| 组件     | 职责                               | 实现                |
| -------- | ---------------------------------- | ------------------- |
| 意图识别 | 理解用户想做什么                   | LLM 分类            |
| 对话管理 | 维护对话状态和上下文               | 状态机 + 上下文管理 |
| 能力路由 | 根据意图分发到对应的能力模块       | 规则 + LLM 路由     |
| 响应生成 | 基于能力模块的输出生成最终回复     | LLM 生成 + 模板     |
| 工具调用 | 需要时调用外部工具（如计算、查询） | Function Calling    |

**设计原则**：

- 单一 Agent，不搞多 Agent 协作（MVP 阶段）
- 意图识别和路由用规则优先，LLM 兜底
- 响应生成有模板就用模板，减少 LLM 调用

**MVP 方案**：

- 意图分类：规则匹配 + LLM（少量标签）
- 能力路由：基于意图的简单路由表
- 响应生成：LLM 为主，关键场景（紧急、免责）用模板
- 工具调用：Function Calling（按需使用）

#### S10：基础设施（Infrastructure）

**支撑的 Agent 能力**：所有系统

**职责**：提供底层技术支撑

| 组件     | 职责                         | MVP 方案                          |
| -------- | ---------------------------- | --------------------------------- |
| 配置管理 | 环境变量、模型参数、系统配置 | pydantic-settings                 |
| 日志系统 | 结构化日志、分级日志         | structlog / loguru                |
| 数据库   | 持久化存储                   | SQLite（MVP）→ PostgreSQL（生产） |
| LLM 网关 | 统一的 LLM 调用接口          | 统一封装层                        |
| 异步框架 | 支持并发和异步处理           | asyncio + fastapi                 |
| 定时任务 | 用药提醒、每日问候等         | APScheduler / Celery              |
| API 网关 | 对外提供 RESTful API         | FastAPI                           |

## 三、系统间依赖关系

```
┌─────────────────────────────────────────────────────────────────┐
│                       Interface Layer                           │
│                   Web UI  │  PWA Notifications                  │
└────────────────────────────┬────────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────────┐
│                     Agent Core (S9)                             │
│          Intent → Route → Execute → Respond                     │
└──┬────────┬────────┬────────┬────────┬────────┬────────────────┘
   │        │        │        │        │        │
   ▼        ▼        ▼        ▼        ▼        ▼
┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐
│Memory││Knowl ││Data  ││Analy ││Comms ││Safety│
│ (S1) ││(S2)  ││(S3)  ││(S4)  ││(S5)  ││(S6)  │
└──┬───┘└──────┘└──┬───┘└──┬───┘└──┬───┘└──┬───┘
   │               │       │       │       │
   ▼               ▼       ▼       ▼       ▼
┌─────────────────────────────────────────────────────────────────┐
│              Infrastructure (S10)                               │
│    Config  │  DB  │  LLM Gateway  │  Logging  │  Scheduler    │
└─────────────────────────────────────────────────────────────────┘
```

**依赖方向**：

- Agent Core 依赖所有基础系统
- 基础系统之间尽可能独立，减少耦合
- 所有系统依赖 Infrastructure
- 严格单向依赖，禁止循环引用

## 四、MVP 实施优先级

> 本节是基础系统的长期建设顺序。`0.0.1` 只建设 ADR-005 垂直闭环实际需要的最小子集，不按目录一次性搭建十个空系统。

| 阶段        | 系统                       | 说明                   |
| ----------- | -------------------------- | ---------------------- |
| **Phase 0** | S10 基础设施               | 项目骨架，必须先搭建   |
| **Phase 1** | S1 记忆系统（画像+时间线） | 其他能力的数据基础     |
| **Phase 1** | S9 Agent 核心引擎          | 对话能力的核心         |
| **Phase 1** | S6 安全合规（基础版）      | 生命线，不可省略       |
| **Phase 1** | S8 会话管理                | 对话的基础             |
| **Phase 2** | S2 知识库                  | 支撑知识问答和风险评估 |
| **Phase 2** | S3 数据采集（NL 解析）     | 支撑体征和症状录入     |
| **Phase 2** | S5 通信系统（推送）        | 支撑主动关怀           |
| **Phase 3** | S4 分析引擎                | 支撑趋势分析和风险评估 |
| **Phase 3** | S7 个性化                  | 提升用户体验           |
